# 폰 클라이언트 — 슬라이스 계획

[ADR 0011](adr/0011-remote-engine-hybrid-client.md) 의 결정을 두 조각으로 나눕니다. **슬라이스 1 은 맥 없이 끝까지 돌아야 하고**, 슬라이스 2 는 맥을 부릅니다. 순서에 이유가 있습니다 — 1 이 먼저여야 relay 가 없을 때 앱이 무엇인지가 정해집니다.

## 슬라이스 1 — 빠른 모드

입력을 받아 온디바이스에서 답하고 Live Activity 로 보여줍니다. **네트워크도 맥도 없이 끝납니다.**

### 필요한 것

| 부분 | 무엇 |
| --- | --- |
| 입력 | App Shortcut(음성·Spotlight) + Control 위젯(제어 센터·잠금화면) |
| 의도 판별 | 일정 조회 / 미리알림 추가 / 그 외 답변 |
| 데이터 | EventKit — 읽기와 쓰기 권한 분리 요청 |
| 답변 | 요약·재작성은 온디바이스 모델, 안 되면 API |
| 표시 | Live Activity. ContentState 는 상태와 한 줄 |

### 기존 코드에서 재사용

- **`src/shared/risk.ts`** — 미리알림 추가는 안전하지만, 빠른 모드에도 되돌릴 수 없는 동작(삭제)이 들어올 수 있습니다. 단어 판정은 그대로 옮깁니다.
- **`src/gate/gate.ts`** 의 `verdictFor`·기본값 거절 — 인터페이스를 Swift 로 옮깁니다. `ApprovalRequest` 는 이미 `macro` 가 선택이라 맥 없이도 성립합니다.
- **`src/trace/`** 의 이벤트 모양 — 폰에서도 무엇을 했는지 줄 단위로 남깁니다. 나중에 두 모드를 한 표에서 비교하려면 지금 같은 모양이어야 합니다.

### 새로 만드는 것

App Shortcut·Control 위젯·EventKit 래퍼·Live Activity·온디바이스 의도 판별. **엔진과 공유하지 않는 코드입니다.**

### 완료 판단

1. 비행기 모드에서 "내일 일정 뭐야" 가 **3초 안에** 답한다.
2. 잠금 상태에서 제어 센터 버튼만으로 미리알림이 추가된다.
3. 권한을 거부한 상태에서 앱이 무엇이 없는지 말하고 죽지 않는다.
4. Live Activity 가 뜨고, 앱을 열지 않아도 결과를 읽을 수 있다.
5. 맥 미니가 꺼져 있어도 위 넷이 전부 성립한다.

**5 번이 이 슬라이스의 존재 이유입니다.** 이게 안 되면 빠른 모드가 아니라 그냥 작업 모드의 앞부분입니다.

## 슬라이스 2 — 작업 모드

매크로를 맥에서 실행시키고 진행·승인·결과를 폰에서 봅니다.

### 필요한 것

| 부분 | 무엇 |
| --- | --- |
| 라우팅 | 발화 → 매크로. 폰에서 판단하지 않고 **맥의 Router 에 맡깁니다** |
| 전송 | relay (아래 설계) |
| 실행 | 기존 `ReplayExecutor` — 손대지 않습니다 |
| 진행 | 스텝마다 Live Activity 갱신 |
| 승인 | `LiveActivityIntent` 버튼 → relay → 맥의 `Gate` |
| 판정 | 매크로의 `assert` 스텝. 모델 판정자는 탐색 경로에만 |
| 결과 | 성공·실패와 이유 한 줄 |

### 기존 코드에서 재사용

거의 전부입니다. **`run.ts` 가 하는 일을 원격에서 시키는 것**이고, 그 함수는 이미 매칭·게이트·실행·판정·저장을 순서대로 합니다. 새 진입점 하나와, 진행 상황을 밖으로 내보내는 훅이 필요할 뿐입니다.

`Gate` 인터페이스는 그대로 두고 **`RelayGate` 를 하나 더 구현**합니다. `TerminalGate` 가 터미널에 묻듯 relay 에 묻습니다. 기본값이 거절인 규칙도 그대로입니다 — 폰이 응답하지 않으면 거절입니다.

### 새로 만드는 것

relay 서버(맥), relay 클라이언트(폰), APNs 푸시, `RelayGate`, 진행 훅.

### 완료 판단

1. 폰에서 발화 → 맥이 매크로를 골라 실행 → 폰에 결과가 뜬다.
2. 되돌릴 수 없는 매크로에서 **승인 없이는 실행되지 않는다.** 폰을 잠가두거나 응답하지 않으면 거절로 끝난다.
3. 실행 중 진행이 스텝 단위로 보인다.
4. 맥 미니가 꺼져 있으면 **큐에 쌓지 않고** 즉시 거절하며 이유를 말한다.
5. 같은 매크로를 두 번 시키면 두 번째가 모델 호출 0회다 — 엔진의 성질이 원격에서도 유지된다.

## relay 설계 초안

### 네트워크 경로

**같은 LAN 만으로는 부족합니다.** 폰이 집 밖에 있을 때가 이 물건을 쓰고 싶은 순간입니다.

**Tailscale(또는 WireGuard) 을 기본으로 둡니다.** 포트 개방 없이 기기 대 기기로 연결되고, 셀룰러에서도 붙고, 네트워크 수준의 신원이 붙습니다. 맥 미니는 tailnet 안에서만 듣습니다.

대안인 공개 인터넷 + 리버스 프록시는 인증을 전부 직접 지어야 하고, 열어둔 포트가 조작 가능한 아이폰 뒤에 있습니다. 채택하지 않습니다.

### 인증

두 겹입니다.

1. **네트워크** — tailnet 밖에서는 맥에 닿지 않습니다.
2. **앱** — 최초 페어링에서 맥이 만든 비밀을 폰의 키체인에 넣고, 모든 요청에 붙입니다. tailnet 안의 다른 기기가 실수로 부르는 것을 막습니다.

**승인 응답은 위조되면 안 됩니다.** 게이트 요청마다 일회용 논스를 만들고, 그 논스로 답한 응답만 받습니다. 논스는 만료됩니다 — 답이 없는 것은 승인이 아닙니다.

### 푸시 토큰 관리

Live Activity 갱신은 **기기 토큰이 아니라 활동마다 발급되는 push token** 을 씁니다. 순서는 이렇습니다.

1. 폰이 작업을 시작하며 Live Activity 를 만들고 그 활동의 push token 을 받습니다.
2. 그 토큰을 relay 로 맥에 보냅니다.
3. 맥이 APNs 에 토큰 기반 인증(p8 키)으로 갱신을 보냅니다.
4. 작업이 끝나면 활동을 닫고 토큰을 버립니다.

**p8 키는 맥 미니에만 둡니다.** 저장소에 들어가지 않습니다 — 이 프로젝트가 공개인 이유가 [ADR 0001](adr/0001-separate-public-repo.md) 에 적혀 있습니다.

페이로드는 4KB 안에 들어가야 하므로 ContentState 에는 **매크로 id·스텝 인덱스·상태**만 담고, 사람이 읽을 문장은 폰이 만듭니다.

### 맥이 꺼져 있을 때

**큐에 쌓지 않습니다.** 한 시간 뒤에 실행되는 요청은 그때의 화면에 대해 아무것도 약속할 수 없고, 되돌릴 수 없는 동작이면 그 간극이 그대로 위험이 됩니다.

폰은 맥에 닿지 않으면 그렇게 말하고, **빠른 모드로만 답합니다.** 슬라이스 1 이 먼저인 이유가 이것입니다 — 그때 앱이 여전히 쓸모 있어야 합니다.

## 판정자 정확도를 슬라이스 2 앞에 둘 것인가

**아닙니다 — 슬라이스 2 를 재생으로 한정하는 한.**

매크로는 자기 `assert` 스텝을 들고 다니고, 그건 사람이 쓴(또는 도출을 거쳐 저장된) 기준입니다. 재생의 성패는 그것으로 갈립니다. **모델 판정자는 `run.ts` 의 탐색 경로에서만 불립니다.**

그래서 순서는 이렇습니다.

- **슬라이스 2 가 재생만 한다** → 판정자 정확도는 선행 조건이 아닙니다.
- **슬라이스 2 에 탐색을 넣는 순간** → 선행 조건이 됩니다. 탐색 결과를 폰에 "성공"으로 띄우려면 그 판정이 얼마나 맞는지 알아야 합니다.

측정 자체는 케이블 한 번에 45런이면 끝나므로(`--executor all --runs 5 --judge`) 미루는 비용이 크지 않습니다. **슬라이스 2 를 재생으로 시작하고, 탐색을 붙이기 전에 재는 것**을 권합니다.

## 아직 확인해야 할 것

조사 문서의 미확인 셋 중 이 방향에 남는 것은 둘입니다.

**스파이크가 준비돼 있습니다** — [`spikes/LockScreenSpike/`](../spikes/LockScreenSpike/README.md). 실기기 체크리스트와 결과를 적을 칸이 거기 있습니다.

| 미확인 | 왜 필요한가 | 확인 방법 |
| --- | --- | --- |
| `LiveActivityIntent` 가 앱을 깨우지 않고 처리되는 범위 | 승인 버튼이 잠금 상태에서 즉시 동작해야 합니다. 앱이 깨어나야 한다면 지연과 실패 지점이 생깁니다 | 빈 프로젝트에 버튼 하나를 두고 잠금 상태에서 눌러 로그를 봅니다 — 슬라이스 1 에서 표시를 만들 때 같이 |
| 잠금 상태에서 Control 위젯이 실행할 수 있는 범위 | 빠른 모드의 완료 조건 2 번이 여기 걸립니다 | 같은 프로젝트에서 EventKit 쓰기를 시도해 봅니다 |

**"단축어가 확인 없이 완주하는 조건"은 더 이상 필요 없습니다** — 단축어 경유안을 채택하지 않았습니다.

## 순서 제안

1. 위 두 미확인을 **작은 빈 프로젝트로 먼저 확인**합니다. 슬라이스 1 의 설계가 여기 달려 있습니다.
2. 슬라이스 1 을 완료 조건 5개까지 닫습니다.
3. 케이블 한 번에 eval 45런 — 판정자 정확도와 스크롤 수정 효과를 같이 얻습니다.
4. 슬라이스 2 를 **재생만으로** 시작합니다.
5. 탐색을 붙이는 것은 그 다음이고, 3번의 숫자를 보고 정합니다.
