# 2026-09-09 — 자가치유 실측

"그냥 매크로 녹화기 아니냐"에 대한 답이 자가치유입니다. [이전 확인](../journal/2026-09-09-self-healing.md)은 스크립트 복구자로 흐름만 검증했습니다. 여기서는 **실제 모델**이 깨진 셀렉터를 고칩니다.

## 측정 조건

| | |
| --- | --- |
| 대상 | iOS Simulator (iPhone 17 Pro) |
| OS | iOS 26.4.1 |
| Xcode | Xcode 26.6 |
| WebDriverAgent | 16.12.5 |
| 앱 | 설정 (com.apple.Preferences) |
| 복구 모델 | `claude-opus-5`, effort high ([ADR 0006](../adr/0006-model-tiering.md)) |
| 반복 | 매크로 × 실행기당 2 |
| 명령 | `npm run heal -- <macro>` |

**깨뜨리는 방법**: 첫 tap 스텝의 식별자에 `.RENAMED`를 붙입니다. 라벨 셀렉터면 라벨을 바꿉니다. 앱 재설계가 남기는 상황과 같습니다 — 한 스텝만 아무것도 못 찾고 나머지는 멀쩡합니다.

## 결과

| 매크로 | 깨진 셀렉터 | 복구 없음 | 복구 있음 |
| --- | --- | --- | --- |
| settings-open-accessibility | `id` | 0/2 | **2/2** |
| settings-open-about | `id` | 0/2 | **2/2** |
| settings-search-open | `label`+`type` | 0/2 | **2/2** |

세 경우 모두 원래 셀렉터를 정확히 복원했고, 깨진 셀렉터는 `alt`로 남았습니다.

```
now  {"id":"com.apple.settings.accessibility"}
alt  {"id":"com.apple.settings.accessibility.RENAMED"}
```

## 복구는 한 번만 값을 치릅니다

이게 측정하려던 진짜 숫자입니다. 복구가 되느냐가 아니라, **된 뒤에 다시 공짜가 되느냐.**

| 매크로 | 1런 | 2런 |
| --- | --- | --- |
| open-accessibility | $0.0069 · 모델 1회 · 복구 1회 · 14915ms | **$0.0000 · 모델 0회 · 8912ms** |
| open-about | $0.0073 · 모델 1회 · 복구 1회 · 16309ms | **$0.0000 · 모델 0회 · 10491ms** |
| search-open | $0.0068 · 모델 1회 · 복구 1회 · 21676ms | **$0.0000 · 모델 0회 · 15490ms** |

2런은 모델을 한 번도 부르지 않고 5~6초 빠릅니다. 고쳐진 셀렉터가 매크로 파일에 써졌기 때문입니다. **앱이 업데이트돼도 첫 실행만 느립니다.**

복구 한 번이 0.7센트입니다. 같은 경로를 탐색으로 다시 찾으면 [$0.0085~$0.0132](2026-09-09-model-tiers.md)이므로, 한 스텝만 깨졌을 때 그 스텝만 올려보내는 쪽이 싼 게 맞습니다. 다만 **차이가 2배 이내**입니다 — 스텝이 셋뿐인 경로에서 "그 스텝만"의 절약은 크지 않습니다. 스텝이 많은 경로일수록 벌어집니다.

## 안 고치는 것도 측정했습니다

복구가 거절해야 하는 경우는 계약 테스트로 확인합니다. 실기가 아니라 기록된 화면 위에서 도는데, **거절은 앱이 실제로 그 상태가 되어야만 재현되는 게 아니기 때문**입니다.

| 상황 | 결과 |
| --- | --- |
| 화면에 비슷한 게 없음 | 매크로 v1 유지, 런 실패 |
| 제안한 요소 번호가 화면에 없음 | 매크로 v1 유지 |
| 좌표로 교체하려 함 | 매크로 v1 유지 |
| **안전한 스텝을 되돌릴 수 없는 컨트롤로 고치려 함** | 매크로 v1 유지 |
| 복구 예산(2회) 초과 | 중단 |

마지막에서 두 번째가 이번에 추가됐습니다. 사라진 `저장` 옆의 `삭제`는 화면상 가장 가까운 후보이고, 복구는 **매크로에 영구히 써집니다.** 잘못된 계획은 런 하나를 버리지만 잘못된 복구는 그 뒤의 모든 런을, 사람이 안 보는 동안 망칩니다. 프롬프트에도 적지만 코드로도 막습니다.

## 이 숫자로 말할 수 없는 것

- **깨뜨린 건 셀렉터 하나씩입니다.** 진짜 재설계는 화면 구조를 바꾸고, 그건 복구가 아니라 재탐색의 영역입니다.
- **모델이 옛 이름을 봤습니다.** `com.apple.settings.accessibility.RENAMED`에는 정답이 그대로 들어 있습니다. 실제 재설계는 그런 힌트를 남기지 않습니다 — **이 실험은 복구의 상한을 잽니다.**
- **복구 모델 스윕을 안 했습니다.** [ADR 0010](../adr/0010-planning-on-sonnet.md)은 계획만 Sonnet으로 내렸고 복구는 Opus에 남겼습니다. 근거는 아직 없습니다.
