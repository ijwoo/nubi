# Overview

## 문제

아이폰을 자연어로 조작하는 데모는 이미 여럿 있습니다. 전부 같은 벽에 부딪힙니다.

**스크린샷 → 모델 → 탭** 왕복이 스텝당 수 초 걸리고, 실제 작업은 15~25스텝입니다. 한 번에 5분이 걸립니다. 스크린샷이 누적되면서 컨텍스트가 터지고, 압축이 걸리고, 더 느려집니다.

흥미로운 데모지만 아무도 두 번은 쓰지 않습니다.

## 통찰

매일 쓰려면 **같은 일을 두 번째 할 때는 빨라져야** 합니다. 사람이 그렇게 하듯이요.

사람은 처음 가보는 앱에서 헤맵니다. 두 번째부터는 헤매지 않습니다. 화면을 새로 해석하는 게 아니라 손이 기억한 경로를 따라갑니다.

그래서 이 프로젝트의 전제는 하나입니다.

> **런타임에 LLM이 길을 찾게 두면 안 된다.**
> 길을 찾는 건 한 번이고, 그 다음은 재생이다. 모델은 길이 막혔을 때만 다시 부른다.

## 접근

요청 하나가 세 갈래 중 하나로 흐릅니다. 자세한 건 [execution-paths.md](execution-paths.md).

1. **탐색(Explore)** — 매크로가 없는 새 요청. 풀 에이전트 루프. 느리고 토큰을 씁니다.
2. **재생(Replay)** — 저장된 매크로 실행. **모델 호출 0회.**
3. **복구(Repair)** — 셀렉터가 깨진 스텝에서만 발동. 고친 결과를 매크로에 되씁니다.

탐색의 산출물이 재생의 재료가 됩니다. 이 순환이 설계의 전부입니다.

## 주장하는 것

| 동일 태스크 | 학습 전 | 학습 후 |
| --- | --- | --- |
| LLM 호출 | ~20회 | **0회** |
| 입력 토큰 | ~120k | **0** |
| 회당 비용 | 측정 예정 | **$0** |
| 평균 소요 | 측정 예정 | 측정 예정 |
| 성공률 | 측정 예정 | 측정 예정 |

**호출·토큰·비용 0은 설계상 확정**입니다. 재생 경로는 API로 소켓을 열지 않으니까요.

**소요 시간과 성공률은 아직 모릅니다.** 추측한 숫자를 쓰지 않습니다. eval 하네스로 실측하고 그때 채웁니다 ([eval-design.md](eval-design.md)).

### 지금까지 실측된 것

측정 장치는 동작하고 바닥 숫자가 있습니다 — 다만 **아직 비교가 아닙니다.** Explore(phase 03)가 없어서 "학습 전"을 잴 수 없습니다.

| 태스크 | 실행기 | 성공 | p50 | 모델 호출 |
| --- | --- | --- | ---: | ---: |
| settings-open-accessibility | scripted | 5/5 | 8787ms | 0 |

시뮬레이터, 애플 기본 앱 기준. 측정 조건과 읽는 법은 [benchmarks](benchmarks/2026-09-09-scripted-baseline.md).

## 주장하지 않는 것

- 범용 비서가 아닙니다. 자주 하는 작업 20개 정도를 빠르게 하는 개인 도구입니다.
- 어떤 앱에서든 되지 않습니다. 접근성 트리가 부실한 앱에서는 좌표 폴백으로 내려가고, 그만큼 잘 깨집니다.
- 무인 실행용이 아닙니다. WDA가 폰을 점유하고, 위험한 액션은 의도적으로 사람 승인을 요구합니다.

## 왜 이걸 만드나

맥은 이미 셸이 있습니다. 파일 접근도 되고 AppleScript도 됩니다. Claude Code로 대부분 됩니다.

**아이폰은 아무 방법도 없습니다.** 여기가 이 프로젝트의 존재 이유입니다.
