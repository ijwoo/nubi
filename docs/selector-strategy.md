# Selector Strategy

요소를 어떻게 찾는가. 매크로가 얼마나 오래 버티는지를 결정하는 부분입니다.

## 우선순위

위에서부터 시도하고, 성공한 것을 매크로에 기록합니다.

| 순위 | 형태 | 안정성 | 비고 |
| --- | --- | --- | --- |
| 1 | `{ "id": "search_btn" }` | 매우 높음 | `accessibilityIdentifier`. 개발자가 명시적으로 붙인 것 |
| 2 | `{ "label": "검색", "type": "Button" }` | 높음 | 표시 텍스트 + 타입 |
| 3 | `{ "labelContains": "햄버거" }` | 중간 | 부분 일치. 동적 텍스트에 씀 |
| 4 | `{ "index": { "type": "Cell", "n": 0 } }` | 낮음 | "첫 번째 셀". 목록 순서에 의존 |
| 5 | `{ "point": [0.5, 0.12] }` | 매우 낮음 | 정규화 좌표. **최후의 수단** |

### 식별자는 추측하지 않는다

WDA는 `accessibilityIdentifier`를 **`rawIdentifier` 필드로 직접 준다.** 이 값이 있으면(null이어도) 그대로 믿는다.

초기 구현은 `name !== label`이면 식별자로 보는 휴리스틱이었다. WDA가 식별자가 없을 때 `name`에 라벨을 대신 넣기 때문인데, 실제 트리를 보니 전용 필드가 있었다. 그리고 휴리스틱이 틀리는 사례도 실재한다 — Apple ID 아이콘은 `rawIdentifier`와 `label`이 둘 다 `"apple.id"`라서, 휴리스틱이라면 진짜 식별자를 버렸을 것이다.

`rawIdentifier` 키 자체가 없는 구버전 WDA에서만 옛 휴리스틱으로 폴백한다. 자세한 경위는 [ADR 0002 측정 결과](adr/0002-ax-tree-over-screenshots.md).

## 왜 좌표를 최후에 두는가

좌표는 세 가지에 동시에 의존합니다. 기기 해상도, 앱 레이아웃, 스크롤 위치. 셋 중 하나만 바뀌어도 엉뚱한 곳을 누릅니다.

더 나쁜 건 **실패가 조용하다**는 점입니다. 셀렉터가 안 잡히면 Repair가 발동하지만, 좌표는 항상 "성공"합니다 — 그냥 잘못된 걸 누를 뿐입니다. 그래서 좌표 탭 뒤에는 `assert`를 반드시 붙입니다.

자세한 논의는 [ADR 0004](adr/0004-selector-priority.md).

## 정규화 좌표

절대 픽셀이 아니라 화면 크기 대비 비율(0~1)로 저장합니다.

```json
{ "point": [0.5, 0.12] }   // 가로 중앙, 세로 12% 지점
```

기기가 바뀌어도 상대 위치는 유지됩니다. 완벽하진 않지만 절대 좌표보다는 훨씬 낫습니다.

## 트리 압축

WDA의 `/source`는 장황합니다. 화면 하나에 수백 개 노드가 나오고 대부분 쓸모없는 컨테이너입니다.

압축 규칙:

```
1. 상호작용 가능한 것만 남긴다      enabled && visible && (hittable || 텍스트 있음)
2. 빈 컨테이너를 접는다             자식이 하나뿐인 래퍼는 통과
3. 필드를 줄인다                    type, label, id, rect, enabled
4. 화면 밖 요소를 버린다
```

결과:

```json
{ "i": 12, "t": "Button", "l": "검색", "r": [20, 88, 60, 32], "e": true }
```

`i`=인덱스, `t`=타입, `l`=라벨, `r`=[x,y,w,h], `e`=활성.

화면당 20~60개 요소, **300~600토큰**. 압축 전 대비 한 자릿수 줄어듭니다.

## 트리가 부실한 앱

커스텀 드로잉이 많은 앱은 `/source`가 의미 없는 컨테이너만 반환합니다. 이때는 스크린샷 + 비전으로 내려갑니다.

```
트리에 상호작용 요소가 3개 미만  →  스크린샷 첨부
```

비전으로 찾은 위치는 좌표 셀렉터로 저장되고, 그만큼 잘 깨집니다. `stats`에 그 사실이 드러나므로 자동 강등이 걸립니다.

## 셀렉터 학습

Repair가 대체 셀렉터를 찾으면 원래 것을 지우지 않고 `alt`로 남깁니다.

```json
{
  "op": "tap",
  "sel": { "label": "검색하기" },
  "alt": { "id": "search_btn" }
}
```

앱이 롤백되거나 A/B 테스트로 두 버전이 오갈 때 `alt`가 잡아냅니다. 실전에서는 이런 일이 생각보다 자주 일어납니다.
