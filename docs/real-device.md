# 실기기에서 돌리기

지금까지의 모든 숫자는 시뮬레이터에서 나왔습니다. 실기기는 세 가지가 다릅니다 — **코드 서명**, **포트**, 그리고 **화면 자체**.

## 왜 다른가

**서명.** 시뮬레이터 빌드는 서명이 필요 없습니다(`CODE_SIGNING_ALLOWED=NO`). 그래서 케이블도 GUI도 없이 SSH로 됩니다. 기기는 개발자 인증서와 프로비저닝이 있어야 하고, WebDriverAgent의 기본 번들 id(`com.facebook.WebDriverAgentRunner`)는 남의 것이라 내 팀으로 등록할 수 없습니다. 그래서 `com.<팀>.WebDriverAgentRunner`로 바꿔 빌드합니다.

**포트.** 시뮬레이터는 맥과 같은 네트워크에 있어서 에이전트가 `127.0.0.1:8100`에 그냥 뜹니다. 기기에서는 **기기의 8100**입니다. `iproxy`가 케이블로 그걸 맥의 8100에 넘겨줍니다. **이걸 빼먹으면 에이전트가 죽은 것과 똑같이 보입니다** — connection refused만 남습니다.

**화면.** 시뮬레이터(iPhone 17 Pro)는 402×874, 실기기(iPhone 14 Pro)는 393×852입니다. 좌표는 정규화해서 저장하므로([ADR 0004](adr/0004-selector-priority.md)) 영향이 없지만, **식별자는 iOS 버전에 따라 달라질 수 있습니다.** 그게 자가치유를 실기에서 시험할 기회입니다.

## 순서

```bash
scripts/preflight.sh
```

Xcode·서명 팀·iproxy·기기 연결·API 키를 한 번에 확인하고, 안 되는 것마다 어떻게 하는지 알려줍니다. 기기 빌드는 실패해도 몇 분 뒤에 xcodebuild 로그 속에서 실패하기 때문에, 먼저 묻는 편이 낫습니다.

폰 쪽에서 미리 해둘 것:

1. 케이블로 연결하고 **잠금 해제**
2. "이 컴퓨터를 신뢰하시겠습니까?" → 신뢰
3. **설정 › 개인정보 보호 및 보안 › 개발자 모드** 켜기 (재부팅합니다)

개발자 모드가 꺼져 있으면 `xctrace list devices`의 온라인 목록에 아예 안 나옵니다.

그 다음:

```bash
scripts/wda.sh --device        # 창 1 — 첫 빌드는 몇 분 걸립니다
npm run live                   # 창 2 — 스모크 테스트
```

`npm run live`가 통과하면 HTTP 표면과 세션 수명이 시뮬레이터와 같게 동작한다는 뜻입니다. 그 위의 모든 것은 기기 종류를 모릅니다.

## 처음 폰에서 해볼 만한 것

**순서에 이유가 있습니다.** 아래로 갈수록 앞의 것이 성립해야 의미가 있습니다.

### 1. 시뮬레이터 매크로가 폰에서도 도는가

```bash
npm run eval -- --executor scripted --runs 3
```

`macros/`의 세 경로는 시뮬레이터(iOS 26.4.1)에서 쓴 것입니다. 폰이 다른 버전이면 식별자가 다를 수 있습니다.

- **다 통과하면** — 설정의 식별자는 버전을 넘어 안정적이라는 뜻입니다.
- **깨지면** 그게 더 흥미롭습니다. 인위적으로 만든 게 아니라 **진짜로 다른 화면**이니까요. 다음 단계로 갑니다.

### 2. 자가치유가 진짜 변화에도 되는가

```bash
npm run heal -- settings-open-accessibility
```

지금까지의 자가치유 측정은 [상한을 잰 것](benchmarks/2026-09-09-self-healing-live.md)입니다 — 식별자에 `.RENAMED`를 붙였으니 정답이 문자열 안에 들어 있었습니다. **폰에서 실제로 다른 식별자를 만나면 그 힌트가 없습니다.** 이 프로젝트에서 아직 답이 없는 질문이고, 여기서 처음 답이 나옵니다.

### 3. 고리가 폰에서 도는가

```bash
npm run nubi -- run "손쉬운 사용 열어줘" --app com.apple.Preferences   # 탐색
npm run nubi -- run "손쉬운 사용 열어줘"                                  # 재생
```

두 번째가 `$0.0000`이면 됩니다.

### 4. 시뮬레이터에 없는 것

폰에만 있는 것들이 여기서 나옵니다.

- **권한 알림.** 시뮬레이터보다 훨씬 자주 뜹니다. 감지는 하지만 **자동으로 답하지 않습니다**([ADR 0008](adr/0008-detect-alerts-never-answer-them.md)) — 런이 `blocked-by-alert`로 멈추면 그게 정상 동작입니다.
- **생체 인증.** 통과하지 못하게 일부러 두었습니다.
- **실제 계정이 든 앱.** 되돌릴 수 없는 동작이 있는 앱은 [승인 게이트](adr/0007-approval-gate-off-device.md)가 붙기 전까지는 피하는 편이 낫습니다. 지금은 게이트가 설계만 있고 배선이 없습니다.

## 연결한 뒤에도 맥이 필요합니다

**한 번 연결하고 폰만 들고 다니는 건 안 됩니다.** 이유가 둘입니다.

**WebDriverAgent는 XCTest 러너입니다.** 맥의 `xcodebuild test-without-building`이 띄우고, **그 프로세스가 끝나면 같이 죽습니다.** 폰에 설치된 앱처럼 혼자 살아있지 않습니다.

**Brain이 맥에서 돕니다.** 탐색·복구·매크로 저장이 전부 Node 프로세스입니다.

더 근본적으로, **iOS에는 앱이 다른 앱을 조작하는 API가 없습니다.** 접근성 제어는 시스템 권한(스위치 제어, VoiceOver)이라 서드파티에 열리지 않습니다. 폰 안에서 도는 버전은 만들 수 없어서가 아니라 **OS가 허용하지 않아서** 없습니다.

### 케이블은 처음만

페어링과 빌드가 끝나면 무선으로 넘어갈 수 있습니다. Xcode에서 무선 디버깅을 켜고(기기 목록에서 "Connect via network"), 에이전트가 뜬 뒤 폰의 주소를 알려주면 됩니다.

```bash
NUBI_WDA_URL=http://192.168.0.42:8100 npm run nubi -- run "..." --app com.apple.Preferences
```

`iproxy`는 케이블용이라 이때는 필요 없습니다. 폰과 맥이 **같은 네트워크**에 있어야 합니다.

### 그래서 현실적인 모양

맥은 켜둔 채로 두고(맥미니를 집에 두는 식), 폰은 같은 네트워크 안에서 돌아다닙니다. 화면 없이 돌아도 됩니다.

**폰만으로 되는 건 조작이 아니라 지시입니다.** 폰에서 말하고 → 릴레이가 맥에 전달하고 → 맥이 경로를 실행하고 → Live Activity로 진행과 승인을 폰에서 봅니다. 그게 [ADR 0007](adr/0007-approval-gate-off-device.md)이 승인 게이트를 조작 대상 기기 **바깥**에 둔 이유이기도 합니다 — 앱 안의 확인 버튼은 에이전트 자신이 누를 수 있으니까요.

**아직 배선되지 않았습니다.** 릴레이와 Live Activity는 pip-any에 있고, 여기에 연결하는 것이 phase 05입니다.

## 맥 자체를 없앨 수 있나 (참고)

맥이 하는 일은 셋입니다 — WDA를 띄우는 XCTest 세션, Brain 실행, 케이블 포트 포워딩. 각각 떼어낼 수 있는 정도가 다릅니다.

### Brain은 지금도 어디서든

Node와 HTTP뿐입니다. `NUBI_WDA_URL`만 있으면 리눅스든 클라우드든 상관없습니다. 다만 WDA를 띄우는 맥은 여전히 필요해서 반쪽입니다.

### 실행 전체를 리눅스로 — 조건부로 가능

[go-ios](https://github.com/danielpaulus/go-ios)가 기기 프로토콜을 직접 말해 **리눅스에서 XCTest 러너를 띄웁니다.** 디바이스 팜들이 쓰는 방식입니다.

```
맥에서 한 번:  WDA .ipa 빌드·서명   (무료 계정 7일 / 유료 1년 주기)
리눅스 박스:   sudo ios tunnel start  →  ios runwda  →  Brain
폰:            그 박스에 케이블 연결
```

GitHub Actions의 macOS 러너로 빌드하면 **맥을 소유하지 않고도** 됩니다.

**리스크가 있습니다.** iOS 17+부터 터널 요구사항이 까다로워졌고, [iOS 26에서 `runwda`가 실패한다는 이슈](https://github.com/danielpaulus/go-ios/issues/631)가 있습니다(닫혀 있으나 해결 내용은 안 보입니다). 확인이 필요합니다.

### 컴퓨터 자체를 없애기 — 안 됩니다

WDA는 XCTest 러너라 호스트 세션이 끝나면 죽습니다. 그리고 **iOS에는 앱이 다른 앱을 조작하는 API가 없습니다.** 접근성 제어는 시스템 권한이라 서드파티에 열리지 않습니다.

Shortcuts/App Intents로 폰 안에서 도는 건 만들 수 있지만 **앱이 노출한 것만** 됩니다. "아무 앱이나"라는 성질을 잃는데, 그게 접근성 트리를 고른 이유 자체입니다([ADR 0002](adr/0002-ax-tree-over-screenshots.md)). 다른 제품이 됩니다.

### 지금 시점의 판단

맥미니가 있으면 **그게 이미 엔진 박스입니다.** 라즈베리파이 + go-ios는 iOS 26 터널 리스크를 안고 이미 가진 기계를 대체하는 일이라, 맥을 사고 싶지 않은 경우에만 의미가 있습니다.

**코드는 바꿀 게 없습니다.** `Hands`가 HTTP 뒤에 있어서 WDA가 어디서 뜨든 위쪽은 모릅니다. 옮기고 싶어지면 `NUBI_WDA_URL` 하나입니다.

## 안 되는 것

- **무선은 아직 안 해봤습니다.** `NUBI_WDA_URL`로 주소를 바꾸는 길은 열어뒀지만, 실제로 확인한 적은 없습니다.
- **무료 계정은 7일**마다 프로비저닝이 만료되어 다시 빌드해야 합니다.
- **`--setup`으로 미리 빌드**해두면 나중이 빠릅니다: `scripts/wda.sh --device --setup`.
