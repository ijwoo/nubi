# 0007. 승인 게이트를 조작 대상 기기 바깥에

**상태**: accepted
**날짜**: 2026-09-08

## 맥락

결제, 삭제, 메시지 전송처럼 되돌릴 수 없는 액션은 자동 실행되면 안 됩니다. 사람의 승인이 필요합니다.

가장 단순한 구현은 아이폰 화면에 확인 다이얼로그를 띄우는 것입니다.

## 결정

승인 요청은 **조작 대상 기기의 화면을 쓰지 않습니다.** relay 서버를 통해 별도 채널로 나가고, 아이폰의 Live Activity(다이나믹 아일랜드)에 표시됩니다. relay를 못 쓰는 환경에서는 맥의 CLI 프롬프트로 폴백합니다.

## 이유

**에이전트가 자기 승인 창을 누를 수 있습니다.** 승인 UI가 WDA가 조작하는 화면 안에 있으면, 원리적으로 에이전트가 그걸 탭할 수 있습니다. 버그로든, 프롬프트 인젝션으로든, 그냥 "승인" 버튼이 다음 스텝처럼 보여서든.

보안 경계는 **에이전트가 도달할 수 없는 곳**에 있어야 의미가 있습니다.

Live Activity는 WDA의 조작 대상이 아닙니다. 앱 화면이 아니라 시스템 UI 레이어이고, XCUITest가 접근하는 요소 트리 바깥입니다.

부수적으로, 이미 pip-any에 relay와 Live Activity 파이프라인이 있어서 새로 만들 게 거의 없습니다.

## 대안

**앱 내 다이얼로그** — 위 이유로 탈락.

**맥 화면에서만 승인** — 안전하지만 폰을 들고 있을 때 맥으로 가야 합니다. UX가 나쁩니다. CLI 폴백으로는 유지합니다.

**승인 없이 allowlist만** — 목록에 없는 건 아예 못 하게. 단순하지만 유연성이 없고, 목록을 넓히는 순간 안전장치가 사라집니다.

## 결과

relay 의존이 생깁니다. [ADR 0001](0001-separate-public-repo.md)의 결정에 따라 어댑터로 격리하고, relay 없이도 동작하게(CLI 폴백) 만듭니다.

승인 대기 중 세션 상태 관리가 필요합니다. 사람이 몇 분간 응답하지 않을 수 있고, 그동안 WDA 세션은 죽을 수 있습니다. 승인 후 재개할 때 [ADR 0005](0005-session-recovery-in-infra.md)의 복구 로직이 동작해야 합니다.

타임아웃은 거부로 처리합니다. 응답 없음을 승인으로 해석하지 않습니다.
