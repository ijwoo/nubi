# 0005. 세션 복구를 인프라에 두고 모델에게 숨김

**상태**: accepted
**날짜**: 2026-09-08

## 맥락

WebDriverAgent 세션은 자주 죽습니다. 앱 전환, 백그라운드 진입, 타임아웃, 기기 잠금에서요. 실전 자동화에서 이건 예외가 아니라 일상입니다.

참고했던 데모 영상에서는 에이전트의 작업 체크리스트에 "앱 세션 재시작"이 **하나의 스텝으로** 올라와 있었습니다.

## 결정

세션 상태 확인과 복구를 Hands 안에서 전부 처리합니다. Brain과 모델은 세션이라는 개념을 모릅니다.

```
Hands.tap(sel)
  ├─ 세션 살아있나 확인
  ├─ 죽었으면 재생성 + 이전 컨텍스트 복원
  ├─ 액션 실행
  └─ 위에서 보기엔 그냥 성공한 호출
```

## 이유

세션 사망은 **인프라 문제이지 작업의 일부가 아닙니다.** 모델의 계획에 이게 등장하면 세 가지가 나빠집니다.

1. **계획이 오염됩니다.** 목표와 무관한 스텝이 궤적에 섞이고, 그게 매크로로 추출되면 매크로에도 인프라 잡음이 들어갑니다.
2. **토큰을 씁니다.** 재시작 판단에 모델 호출이 들어갑니다.
3. **비결정적입니다.** 모델이 재시작을 할 수도, 다른 걸 시도할 수도 있습니다.

사람이 웹 자동화를 짤 때 TCP 재연결을 스크립트에 넣지 않는 것과 같습니다.

## 대안

**모델이 처리** — 유연해 보이지만 위 세 문제를 다 갖습니다.

**Brain이 처리** — Hands보다는 낫지만 Brain이 WDA의 세부를 알아야 합니다. 경계가 흐려집니다.

## 결과

Hands의 모든 공개 메서드가 재시도 래퍼를 통과합니다. 액션이 **멱등해야** 이게 안전합니다 — 탭을 두 번 하면 안 되는 경우가 있으므로, 재시도 전에 화면 상태를 확인해서 이미 적용됐는지 판단합니다.

이 판단이 100% 정확할 수는 없습니다. 확실하지 않으면 재시도하지 않고 실패로 올립니다. 조용한 이중 실행보다 명시적 실패가 낫습니다.
