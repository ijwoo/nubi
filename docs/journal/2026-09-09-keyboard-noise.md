# 2026-09-09 — 키보드가 예산을 먹고 있었다

## 태스크가 하나뿐이었다

phase 03 코드는 다 됐는데 API 키가 없어서 Explore를 못 돌린다. 그동안 뭘 할까 보다가, **eval 태스크가 하나뿐**인 게 눈에 들어왔다.

하나로는 Explore와 scripted를 비교해봐야 아무것도 증명되지 않는다. 같은 모양을 두 방식으로 재는 것뿐이다.

그래서 **상호작용 모양이 다른** 태스크를 찾으러 시뮬레이터를 뒤졌다.

## 조사하다 걸린 것

후보 경로를 걸어보는 스크립트를 짜서 돌렸다. 설정 > 일반 > 정보, 설정 검색, 미리알림.

설정 검색 화면에서 숫자가 이상했다.

```
--- 검색 결과  (40 el, ~828 tok) ---
   0 StaticText  ‘손쉬운’에 대한 결과 없음
   2 SearchField 검색
   6 Key         Q
   7 Key         W
   8 Key         E
   ...
```

**828토큰.** [ADR 0002](../adr/0002-ax-tree-over-screenshots.md)의 목표가 600이고, 테스트 상한이 800이다. 넘었다.

40개 요소 중 **26개가 키보드 자판**이었다.

## 왜 안 보였나

이걸 여태 못 본 이유가 있다. 지금까지 측정한 화면 — 설정 루트, 일반, 손쉬운 사용, 지도, 미리알림, 캘린더 — **어디에도 키보드가 없었다.**

텍스트 입력이 들어가는 태스크를 만들려고 하니까 처음 나온 화면이다. 태스크를 늘리려던 작업이 압축 규칙의 구멍을 찾아준 셈이다.

## 자판은 볼 이유가 없다

잠깐 고민했다. 키보드를 지우면 모델이 타이핑을 못 하는 것 아닌가?

아니다. **우리 액션 어휘에서 타이핑은 `type` 액션이고, WDA가 포커스된 요소에 텍스트를 보낸다.** 글자를 하나씩 눌러서 입력하지 않는다.

그러니까 자판 26개는 **모델이 누를 수 없는 것들**이다. 보여주는 건 토큰과 자리를 둘 다 낭비하는 것이고, 더 나쁘게는 진짜 컨트롤을 밀어낸다.

`Key` 타입만 제외했다. 커스텀 키패드가 `Button`으로 그려진 경우는 남는다 — 거기서는 버튼이 정말 유일한 입구다.

## 결과

```
40요소 828토큰  →  14요소 325토큰
```

그리고 가려져 있던 게 드러났다.

```
  StaticText   제안
  Button       앱
  Button       개발자
  Button       손쉬운 사용        ← 이게 안 보이고 있었다
  Button       개인정보 보호 및 보안
  SearchField  검색
```

검색 제안 목록이다. 자판에 밀려서 위쪽에 있었을 뿐인데 40개 중에 파묻혀 있었다.

**노이즈를 걷어내니 실제 컨트롤이 보였다.** 토큰을 줄인 것보다 이게 더 중요할 수 있다 — 모델이 볼 수 있는 게 늘었다.

## 압축이 못 고치는 것

검색 태스크가 15.3초로 다른 둘(9.0초, 10.5초)보다 5~6초 느리다.

```
act     3926ms  tap 검색창
act     3678ms  type "손쉬운"
```

키보드 화면은 **원시 트리가 321노드 115KB**다. 설정 루트가 168노드 61KB이니 두 배다. WDA가 그걸 직렬화하는 시간은 우리가 어쩔 수 없다.

**압축은 토큰을 줄이지만 응답 시간은 못 줄인다.** 받는 건 여전히 전체 트리다. 이건 최적화 여지로 남겨둔다 — WDA는 특정 요소로 범위를 좁히는 것도 지원한다.

## 태스크 셋

결국 셋으로 늘렸다. 모양을 일부러 다르게 했다.

| 태스크 | 모양 | p50 |
| --- | --- | ---: |
| settings-open-accessibility | 목록 → 상세 | 8959ms |
| settings-open-about | 2단계 중첩 | 10541ms |
| settings-search-open | 포커스 → 입력 | 15337ms |

**세 번째가 Explore에게 가장 어려울 것 같다.** 순서가 있는 두 액션이고, 틀리면 조용히 실패한다 — 필드를 안 누르고 `type`을 하면 성공을 반환하면서 텍스트만 사라진다.

그 실패가 트레이스에 어떻게 남는지가 궁금하다.

## 시뮬레이터의 한계 하나

설정 검색이 **어떤 검색어를 넣어도 결과가 없다.** 색인이 안 만들어진 것 같다.

그래서 "검색해서 결과를 연다"는 태스크는 못 만들고, "검색창에 입력한다"까지만 잰다. 판정도 결과 목록이 아니라 **"텍스트 지우기" 버튼이 생겼는지**로 한다 — 입력이 실제로 들어갔다는 증거다.

미리알림은 온보딩 화면("미리 알림 시작하기")이 떠서 첫 실행과 이후 실행이 다르다. eval에는 부적합해서 이번엔 뺐다.

## 배운 것

**측정 대상을 늘리려다 측정 도구의 버그를 찾았다.**

태스크가 하나였을 때는 규칙이 완벽해 보였다. 새 화면 하나가 들어오자 바로 깨졌다. 앱을 더 넣으면 또 나올 것이다 — 웹뷰, 지도, 커스텀 그리기.

**압축 규칙은 본 화면만큼만 옳다.**
