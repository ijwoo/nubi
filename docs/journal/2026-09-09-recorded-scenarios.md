# 2026-09-09 — 계약 하나, 두 구현

## 인터페이스가 같다고 동작이 같지는 않다

`FakeHands`와 `WdaHands`는 같은 `Hands`를 구현한다. TypeScript가 통과시킨다.

그게 아무것도 보장하지 않는다는 걸 짚고 넘어가야 했다. **TypeScript는 모양을 검사하지 실행 결과를 검사하지 않는다.** 실기는 성공하는데 가짜는 미스를 반환하는 구현도 타입은 완벽하게 통과한다. 그리고 이 프로젝트 전체가 "가짜 위에서 replay·repair·explore를 만들고 나중에 기기로 갈아끼운다"는 전제에 얹혀 있다.

그래서 계약을 `src/hands/contract.ts`에 **vitest와 무관한 순수 함수 배열**로 뒀다.

```
npm test      → CONTRACT 를 FakeHands 에      (CI)
npm run live  → 같은 CONTRACT 를 WdaHands 에  (기기 필요)
```

정의가 하나라서 조용히 어긋날 수 없다.

계약은 두 구현이 **정직하게 약속할 수 있는 것만** 검사한다. 특정 앱의 화면 전환 지식이 필요한 건 각자의 테스트로 간다.

## 첫 실행에서 4개가 깨졌다

가짜에선 13개 전부 통과했다. 실기에 돌리니 4개가 실패했다.

```
✗ find resolves a selector that is present   expected to find com.apple.settings.general
✗ a label selector matches too
✗ tap falls back to the selector a repair replaced
✗ assert succeeds on something already present   timeout
```

계약 위반이 아니었다. **앞선 액션 검증이 설정 앱을 검색 결과 화면에 남겨놓은 것**이었다. 계약 앞에 `launch`를 넣어뒀는데, 이미 실행 중인 앱에 `launch`를 하면 포그라운드로 올라올 뿐 초기 화면으로 안 돌아간다.

인터페이스로는 안 드러나는 차이가 여기 있었다. **가짜는 케이스마다 새로 만들어지고, 기기는 기억한다.**

`ContractContext`에 `reset()`을 넣고, 케이스마다 먼저 부르게 했다. `launch`에는 `restart` 옵션이 생겼다 — terminate 후 launch. 계약 때문에 억지로 넣은 게 아니라, 매크로가 "앱의 첫 화면부터 시작"을 원할 때 어차피 필요한 것이었다. 기존 옵션 중에 그걸 뜻하는 게 없었다.

고치고 나니 13개 전부 양쪽에서 통과한다.

## 픽스처를 진짜로 바꿨다

`music-*.json`은 내가 상상해서 쓴 것들이다. `XCUIElementType` 접두사가 붙어 있는데 실제 WDA는 짧은 형태로 준다는 걸 [어제](2026-09-09-real-trees.md) 알았다.

`scripts/record.ts`를 만들어서 실제 앱을 걸어다니며 녹화하게 했다.

```
npm run record -- settings

  root             16 elements  4718990ac133
  general          29 elements  5e4b8307857c
  root-again       17 elements  e860b888a8fd
  accessibility    31 elements  4d5bb2b8df70
```

화면 4개, 전이 3개. 전부 실제 WDA 덤프고, 전이는 실제로 발동한 것들이다.

**`root`와 `root-again`의 해시가 다르다.** 16요소 → 17요소. 일반 설정에 들어갔다 뒤로 나오면 처음 화면과 완전히 같지 않다. 손으로 픽스처를 썼다면 당연히 같게 만들었을 것이고, **"뒤로 가면 본 적 있는 화면으로 돌아온다"는 잘못된 가정**을 매크로 리플레이에 심었을 것이다.

레코더는 전이 후 해시가 안 바뀌면 실패로 처리한다. 아무것도 안 바뀐 전이를 녹화하면 가짜가 "아무 일도 안 일어남"과 구분할 수 없어진다.

## 녹화 형식에서 한 번 걸렸다

레코더가 트리를 그대로 저장했는데 로더는 `{value: tree}` 봉투를 기대했다. `unknown start screen "root"`.

레코더를 WDA 봉투 형태로 쓰게 고쳤다 — 녹화본이 curl로 뜬 덤프와 구별되지 않아야 맞다. 로더는 양쪽 다 받게 했다.

## 손으로 쓴 픽스처는 안 지웠다

`music-*.json`을 지울까 하다 뒀다.

어제 진짜 데이터로 압축 규칙을 고칠 때, **과잉 수정을 잡아준 게 손으로 쓴 픽스처였다.** `dropPresentation`을 "탭 가능한 조상 안이면 전부 제거"로 짰더니 설정 앱에선 완벽했는데, 곡 제목 셀 안의 아티스트 이름이 지워지는 걸 가짜 픽스처가 잡았다.

진짜 데이터는 **실제로 일어나는 일**을 알려주고, 손으로 만든 데이터는 **일어날 수 있는 일**을 알려준다. 둘 다 있어야 한다.

## 남은 찜찜함

- 시뮬레이터 트리와 실기기 트리가 얼마나 다른지 여전히 모른다. 계약은 시뮬레이터에서만 돌려봤다.
- App Store 앱(트리가 부실할 가능성이 높은 쪽)은 시뮬레이터에 못 깐다. 압축 규칙이 애플 기본 앱에만 잘 맞을 수 있다.
- 녹화 픽스처가 1.2MB다. 앱을 늘리면 금방 커진다. 언제 압축하거나 잘라낼지 정해둬야 한다.
