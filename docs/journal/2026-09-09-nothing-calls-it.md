# 2026-09-09 — 아무도 부르지 않는 코드를 찾는 검사

[고리를 닫으면서](2026-09-09-closing-the-loop.md) `extractMacro`가 **테스트가 다 통과하는 죽은 코드**였다는 걸 알았다. 같은 게 또 있는지 찾아봤다.

있었다.

```
recordRun  —  src/macro/store.ts
```

매크로의 실행 횟수·실패 횟수·평균 시간을 기록하는 메서드다. 자기 테스트 밖에서 **한 번도 호출되지 않았다.**

그래서 `stats`가 영원히 0이고, `isDemoted`는 `runs >= 5`를 요구하니 **어떤 매크로도 강등될 수 없었다.** 실패율 30% 넘으면 라우팅에서 뺀다는 규칙이 실행된 적이 없다.

## 커버리지가 잡을 수 있는 게 아니다

두 함수 모두 **덮여 있었다.** 입력을 주면 옳은 출력을 냈고 테스트가 그걸 확인했다.

안 덮인 건 **누군가 그 함수를 부른다는 사실**이고, 그건 어떤 단위 테스트의 주제도 아니다. 단위 테스트는 정의상 단위를 검사한다.

그래서 그 질문을 직접 하는 검사를 만들었다. **`bin/`이나 `scripts/`에서 이 export까지 가는 길이 있나, 아니면 테스트되기 위해서만 존재하나.**

## 검사가 자기 발을 세 번 밟았다

**1. 같은 파일 안의 사용을 통째로 뺐다.** 13개가 걸렸는데 대부분 `hashElements`처럼 자기 모듈이 부르는 것들이었다. 묻고 싶은 건 "export할 필요가 있었나"가 아니라 **"이게 제품에서 도는가"** 다. 같은 파일에서 부르는 것도 도는 것이다. 규칙을 좁혔더니 하나로 줄었다.

**2. `recordRun`을 못 잡았다.** 정규식이 `export function|class|const`만 봤는데 `recordRun`은 **메서드**다. 이 검사를 쓰게 만든 바로 그 케이스를 놓쳤다. 클래스 메서드까지 보게 고쳤다.

**3. 그래도 못 잡았다.** 이번엔 더 낫다 — **이 파일의 주석이 `recordRun`을 언급하고 있었다.** 검사가 자기 설명문으로 자기 발견을 지우고 있었다. 세기 전에 주석을 걷어냈다.

세 번 다 검사 자체가 틀렸고, 세 번 다 "결과가 깨끗하다"로 보였다. **오늘 다섯 번째다.**

## 덤으로 하나

`readTrace`도 걸렸다. 찢어진 마지막 줄을 건너뛰고 트레이스를 읽는 함수다.

지우려다 봤더니 [모델 비교 스크립트](../benchmarks/2026-09-09-model-tiers.md)에서 내가 같은 일을 생 `JSON.parse`로 다시 짜놨다. **중간에 죽은 런의 트레이스를 읽으면 크래시한다** — 그리고 중간에 죽은 런이야말로 읽어볼 가치가 있는 런이다.

죽은 export 하나가 다른 곳의 버그를 가리키고 있었다.

## 지금은 CI에 있다

```
wiring ok — 106 exports, all reachable
```

예외는 셋뿐이고 각각 이유가 붙어 있다 — 가짜 백엔드의 `goto`·`showAlert`, 계약 목록 `CONTRACT`. **목록이 짧은 게 핵심이다.** 진짜 발견이 손사래로 지워지는 자리라서, 모든 항목은 읽는 사람이 바로 수긍할 만한 것이어야 한다.

## 알림도 손봤다

실기에서 가장 흔할 실패를 미리 손봤다. 권한 알림이 뜨면 모든 터치가 흡수되는데 `/source`는 멀쩡한 트리를 계속 준다. [시뮬레이터에서 세 번 헛짚었던](2026-09-09-touch-into-the-void.md) 그 상황이고, 폰에서는 일상이 될 것이다.

지금까지는 `경로를 찾지 못함`으로 보고했다. 경로가 문제였던 적이 없는데.

```
✗ 탐색  시스템 알림이 막고 있습니다 — "“설정”이 위치 정보에 접근하려고 합니다"  [허용 안 함 / 허용]
```

여전히 **대신 답하지 않는다**([ADR 0008](../adr/0008-detect-alerts-never-answer-them.md)). 할 수 있는 유용한 일은 무엇이 막고 있는지 말해주는 것뿐이다.

## 배운 것

테스트가 초록인 것과 코드가 도는 것은 다른 질문이고, **두 번째 질문을 하는 도구가 없었다.**

`extractMacro`는 사람이 우연히 발견했다 — "지금 되는 기능이 뭐냐"는 질문에 답하려다가. `recordRun`은 그 발견이 만든 검사가 찾았다. 세 번째가 있다면 이제 CI가 찾는다.
