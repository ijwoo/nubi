# 2026-09-08 — 시작

## 발단

인스타 릴스에서 맥에서 Codex를 돌려 아이폰을 음성으로 조작하는 영상을 봤다. 유튜브 뮤직에서 노래를 틀고, 쿠팡이츠에서 햄버거를 찾는 데모였다.

처음엔 iPhone 미러링을 쓴 줄 알았다. 두 번째 스크린샷에서 아이폰 화면에 **"Automation Running — Hold both volume buttons to stop"** 배너가 보였다. 미러링이 아니라 실기기에 XCUITest 러너(WebDriverAgent)가 붙어 있는 거였다. 옆에 있던 건 미러링 창이 아니라 크림색 케이스를 낀 진짜 아이폰.

영상 자막이 "오래걸리는데 그래도 되게 신기함"이었고, 터미널에는 `Worked for 5m 38s`와 `Context compacted`가 찍혀 있었다.

## 문제를 어디서 봤나

5분이 걸린 것 자체보다, **작업 체크리스트에 "쿠팡이츠 세션 재시작"이 하나의 스텝으로 올라와 있던 게** 더 눈에 띄었다. WDA 세션 사망은 상시 발생하는 인프라 문제인데, 그게 에이전트의 계획에 섞여 있었다. 모델이 알 필요가 없는 일이다.

그리고 `Context compacted` — 스크린샷을 스텝마다 쌓으면 20스텝 만에 컨텍스트가 터진다. 압축이 걸리면 정보를 잃고 더 느려진다.

두 가지가 같은 곳을 가리켰다. **런타임에 LLM이 너무 많은 일을 하고 있다.**

## 전제

사람은 처음 가보는 앱에서 헤맨다. 두 번째부터는 헤매지 않는다. 화면을 다시 해석하는 게 아니라 손이 기억한 경로를 따라간다.

그래서 이렇게 잡았다.

> 길을 찾는 건 한 번이고, 그 다음은 재생이다. 모델은 길이 막혔을 때만 다시 부른다.

처음 성공한 경로를 **셀렉터 기반 매크로**로 저장하고, 두 번째부터는 모델 호출 없이 재생한다. 셀렉터가 깨지면 그 스텝만 모델에 올려서 고치고, 고친 결과를 매크로에 되쓴다.

## 이름 고르는 데 시간이 걸렸다

처음 제안받은 건 `muscle-memory`였다. 기술 핵심이 이름에 그대로 있어서 설명이 짧아진다는 논리였는데, 너무 길고 설명적이었다.

`Pixie`, `Nixie`, `Kiki` 같은 요정·사람 이름 계열로 갔다가 — 너무 캐릭터 이름 같았다.

`Thimble`(골무), `Nudge`(툭 밀다), `Crumb`(빵부스러기) 같은 사물·동작 단어로도 가봤다. `Crumb`은 은유가 좋았다. 헨젤과 그레텔이 길에 부스러기를 떨어뜨리고 다음엔 그걸 따라가는 것 — 매크로 시스템 그 자체. 근데 "부스러기"가 주는 하찮은 톤이 걸렸다.

결국 에이닷 같은 **짧은 브랜드 조어** 쪽으로 방향을 잡고 `Nubi`로 정했다. 한국어 "누비다"에서 왔다. 앱 화면을 이리저리 누비고 다니며 대신 눌러주는 비서.

한국어 뿌리가 있어서 설명할 스토리가 생기고, 발음은 국제적으로도 어렵지 않고, 사람 이름 느낌은 안 나면서 브랜드처럼 들린다.

(`nudge`랑 `recall`은 이미 `~/dev`에 폴더가 있어서 어차피 못 썼다.)

## 초기 스케치에서 바뀐 것

처음엔 Hands를 별도 HTTP 서비스로 두려 했다. 크래시 격리가 이유였는데, v1에서는 과했다. HTTP 레이어 하나가 통째로 늘어나는 대신 얻는 게 없었다.

Hands는 라이브러리로 바꿨다. Brain이 in-process로 import 한다. 대신 MCP 서버 어댑터를 얇게 얹어서, 개발 중에 Claude Code가 직접 폰을 조작할 수 있게 한다. 이게 디버깅에 훨씬 유용할 것 같다.

## 순서에 대한 판단

phase 순서를 이렇게 잡았다.

```
01 Hands  →  02 Trace+Eval  →  03 Explore  →  04 Macro  →  05 Orb
```

**eval을 매크로보다 앞에** 뒀다. 이 프로젝트의 주장은 "학습하면 빨라진다"인데, 그걸 증명하려면 "학습 전" 숫자가 있어야 한다. 매크로를 먼저 만들어버리면 그 숫자를 잴 기회가 영영 사라진다.

측정 인프라가 앞에 서야 한다.
