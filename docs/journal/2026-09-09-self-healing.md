# 2026-09-09 — 자가치유가 실제로 도는 걸 확인했다

## "그냥 매크로 녹화기 아니냐"

이 프로젝트에 올 가장 날카로운 반문이다. 처음 [설계 스펙](../../README.md)을 쓸 때부터 적어뒀다.

답은 자가치유다. 앱이 바뀌어서 셀렉터가 깨졌을 때 **그 스텝만** 모델에 올라가고, 고쳐진 셀렉터가 매크로에 되쓰인다. 녹화기는 그걸 못 한다.

API 키가 없어서 모델 부분은 못 돌리지만, **모델을 인터페이스 뒤로 빼면 나머지는 전부 검증된다.** `Planner`를 그렇게 만든 것과 같다.

## 깨진 매크로를 만드는 건 쉬웠다

앱 업데이트를 기다릴 필요가 없다. 셀렉터를 존재하지 않는 식별자로 바꾸면 된다.

```json
{ "op": "tap", "sel": { "id": "com.apple.settings.accessibility.RENAMED" } }
```

재설계가 남기는 상황과 같다 — **한 스텝만 아무것도 못 찾고 나머지는 멀쩡하다.**

## 실기 결과

```
1) 복구 없이 — scripted    0/2 성공
2) 복구 있음 — replay      2/2 성공
3) 매크로                  v1 → v2, healedAt 기록됨

   step 1: { sel: {id: "...accessibility"},
             alt: {id: "...accessibility.RENAMED"} }
```

`복구 0회`로 보고된 게 처음엔 이상했는데, 맞는 동작이었다. **첫 런에서 고쳐서 저장했으니 두 번째 런은 이미 멀쩡한 매크로를 받는다.** 복구는 한 번만 값을 치른다.

## scripted를 안 지웠다

`ScriptedExecutor`(복구 없음)와 `ReplayExecutor`(복구 있음)를 둘 다 남겼다.

지울 뻔했는데 — 남겨두면 **복구가 실제로 뭘 벌어주는지 측정할 수 있다.** 위 0/2 대 2/2가 그 숫자다. 없으면 "자가치유됩니다"는 주장이지 결과가 아니다.

## 거절해야 하는 복구

고치는 것만큼 **안 고치는 게 중요한** 경우들이 있다.

**좌표로 교체하려 할 때.** 이름 있는 컨트롤을 좌표로 덮어쓰면 한 번 되고 다시 깨진다. 그리고 그 스텝이 원래 뭐였는지가 사라진다. **실패하고 탐색이 진짜 경로를 찾게 하는 편이 낫다.**

**화면에 비슷한 게 없을 때.** 복구자가 `undefined`를 반환하면 매크로를 건드리지 않는다. 아무거나 눌러보는 것보다 실패가 낫다.

**복구 예산을 넘을 때.** 스텝마다 고쳐야 하는 경로는 **바뀐 게 아니라 없어진 것**이다. 전부 다시 쓰면 아무도 선택하지 않은 매크로가 남는다. 기본값은 런당 2회.

## alt를 남기는 이유

교체된 셀렉터를 버리지 않고 `alt`로 남긴다.

롤백이나 A/B 테스트로 옛 화면이 돌아올 수 있다. 그런데 더 중요한 게 있다 — **`alt`로만 계속 성공하는 매크로는 그 복구가 틀렸다고 말하는 것이다.** 셀렉터 해석기가 어느 쪽이 맞았는지 보고하니까(`via: 'sel' | 'alt'`), 나중에 이걸로 잘못된 복구를 찾아낼 수 있다.

## 매크로 저장소

복구가 파일을 고쳐야 해서 저장소를 먼저 만들었다.

**임시 파일에 쓰고 rename한다.** 런이 중간에 죽으면 잘린 매크로가 남고, 다음 런이 한 시간 전까지 잘 돌던 경로를 파싱 못 하게 된다.

**평균은 성공한 런만 센다.** 실패한 런의 소요 시간은 "포기하는 데 걸린 시간"이라 다른 값이다. 섞으면 둘 다 설명하지 못하는 숫자가 나온다.

**깨진 파일은 조용히 건너뛰지 않고 던진다.** 무시하면 매크로가 라우팅에서 사라지는데 이유를 알 수가 없다.

## 강등

실패율이 30%를 넘고 5회 이상 돌았으면 라우팅에서 뺀다.

**자주 실패하는 매크로는 없느니만 못하다.** 매번 런 하나를 태우고 나서야 탐색으로 넘어간다.

지우지는 않는다. 스텝은 여전히 누군가 가진 가장 좋은 출발점이고, 복구가 되살릴 수도 있다.

## 남은 것

`ClaudeRepairer`가 없다. 인터페이스는 있고 스크립트 구현으로 검증했지만, 실제 프롬프트는 키가 있어야 쓸 수 있다.

그리고 **탐색이 찾은 경로를 매크로로 뽑는 것**이 아직이다. `ExploreExecutor.route`가 셀렉터 목록을 이미 들고 있어서 재료는 있는데, 이름·파라미터를 정하는 부분이 남았다.
