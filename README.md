# Nubi

**말로 시키면 아이폰이 대신 움직입니다. 한 번 찾은 길은 다음부터 모델 없이 재생합니다.**

> `nubi` — 순우리말 *누비다*에서. 앱 화면을 이리저리 누비고 다니며 대신 눌러줍니다.

접근성 트리를 읽고, 눌러야 할 컨트롤을 찾고, 탭합니다. 처음엔 길을 찾아야 하지만 그 다음부터는 기억한 경로를 따라갑니다.

> **엔진은 맥에서 돕니다. 폰 혼자서는 안 됩니다.**
>
> iOS 에는 앱이 다른 앱을 조작하는 API 가 없습니다. 접근성 제어는 시스템 권한이라 서드파티에 열리지 않고, 이건 만들기 어려운 게 아니라 **OS 가 허용하지 않는** 것입니다. 그래서 조작은 WebDriverAgent 를 통해 이루어지고, 그건 폰에 설치된 앱이 아니라 맥이 띄우고 유지하는 XCTest 러너입니다.
>
> 실제 모양은 이렇습니다 — **맥(또는 리눅스 박스)이 켜져 있고, 폰은 케이블이나 같은 Wi‑Fi 로 닿습니다.** 집에 맥미니를 두는 식이면 폰은 들고 다녀도 됩니다. 앱스토어에 올릴 수 있는 물건은 아닙니다.
>
> 폰이 맡을 수 있는 건 조작이 아니라 **지시와 승인**입니다 — 말하고, 진행을 보고, 되돌릴 수 없는 일을 승인하는 쪽. 그게 [ADR 0007](docs/adr/0007-approval-gate-off-device.md) 이 승인 게이트를 조작 대상 기기 바깥에 둔 이유이기도 합니다.

---

## 문제

"AI가 폰을 조작한다"는 데모는 전부 같은 벽에 부딪힙니다. **스크린샷 → 모델 → 탭** 왕복이 스텝당 수 초 걸리는데 실제 작업은 15~25스텝입니다. 한 번에 5분이 걸리고, 스크린샷이 쌓이면서 컨텍스트가 터집니다.

재밌는 데모지만 아무도 두 번은 쓰지 않습니다.

매일 쓰려면 **두 번째가 빨라야** 합니다. 사람이 그러듯이요.

## 접근

Nubi는 **길을 찾는 것**과 **길을 따라가는 것**을 분리합니다.

첫 실행은 풀 에이전트 루프입니다. 화면을 보고, 판단하고, 실행하고, 반복. 느리고 토큰을 씁니다. 대신 성공하면 그 경로를 **셀렉터 기반 매크로**로 저장합니다.

다음 실행은 그 매크로를 그대로 재생합니다. 모델 호출이 없습니다. 셀렉터가 깨지면 — 앱이 업데이트됐다든지 — **그 스텝만** 모델로 올라가고, 고쳐진 셀렉터가 매크로에 되쓰입니다.

한 번 찾고, 계속 재생하고, 깨지면 고칩니다.

## 결과

같은 태스크 3개를 두 실행기로 5회씩, 시뮬레이터에서 잰 결과입니다. 탐색은 기본 모델(`claude-sonnet-5`) 기준입니다.

| 동일 태스크 | 첫 실행 (탐색) | 학습 후 (재생) |
| --- | --- | --- |
| 모델 호출 | 2~3회 | **0회** |
| 토큰 | 1.9k~2.7k | **0** |
| 회당 비용 | $0.009~$0.013 | **$0** |
| 소요 시간 | 10.0s~21.6s | 8.9s~15.4s |
| 성공률 | 15/15 | 15/15 |

재생 시 호출·토큰·비용이 0인 것은 **구조적 사실**입니다 — 재생 경로는 API로 소켓을 열지 않습니다. 나머지는 이 기기 이 조건에서 잰 값입니다.

태스크별로는 이렇습니다. 아래 탐색 열은 `claude-opus-5`로 잰 값입니다 — 두 실행기를 같은 조건에서 비교한 회차입니다.

| 태스크 | 모양 | 실행기 | 성공 | p50 | p95 | 모델 | $/런 |
| --- | --- | --- | --- | ---: | ---: | ---: | ---: |
| settings-open-accessibility | 목록 → 상세 | 재생 | 5/5 | 8877ms | 8977ms | 0 | — |
| | | 탐색 | 5/5 | 11208ms | 11879ms | 2 | $0.0141 |
| settings-open-about | 2단계 중첩 | 재생 | 5/5 | 10366ms | 10631ms | 0 | — |
| | | 탐색 | 5/5 | 17322ms | 18764ms | 3 | $0.0229 |
| settings-search-open | 포커스 → 입력 | 재생 | 5/5 | 15429ms | 15559ms | 0 | — |
| | | 탐색 | 5/5 | 23436ms | 24178ms | 3 | $0.0170 |

**속도 차이는 1.3~1.5배로, 극적이지 않습니다.** 두 실행기가 같은 기기를 쓰기 때문입니다 — 앱 실행 4~5초는 모델이 없어도 그대로입니다. 재생이 의미 있는 쪽은 비용입니다: 하루 20번 쓰는 동작이면 탐색만으로 월 $5~8, 매크로로 굳히면 $0입니다.

세 티어를 같은 태스크로 돌려본 결과 **Sonnet이 Opus와 성공률·경로가 같고 40% 쌌습니다.** Haiku는 두 태스크에서 제일 쌌지만 순서가 있는 태스크에서 완료를 인식하지 못해 25수를 헤매며 가장 비쌌습니다 ([ADR 0010](docs/adr/0010-planning-on-sonnet.md), [스윕](docs/benchmarks/2026-09-09-model-tiers.md)).

측정 조건과 읽는 법은 [`docs/benchmarks/`](docs/benchmarks/2026-09-09-explore-vs-scripted.md)에 있습니다. **조건 없는 숫자는 재현할 수 없고, 재현할 수 없는 숫자는 없느니만 못합니다.**

## 한 번의 요청

```bash
npm run nubi -- run "설정 검색창에 손쉬운 입력해줘" --app com.apple.Preferences
```

저장된 경로가 있으면 재생하고, 없으면 탐색해서 **찾은 경로를 저장합니다.** 실기 기록:

```
1회차  ✓ 탐색  24403ms  $0.0105  → "route" 로 저장
2회차  ✓ 재생  16256ms  $0.0000
3회차  ✓ 재생  16371ms  $0.0000   ← "화면" 으로 물어도 같은 경로
```

세 번째가 파라미터입니다. 발화에서 입력한 말이 슬롯이 되어 `설정 검색창에 {arg1} 입력해줘`로 저장되므로, 단어만 바꾼 요청은 탐색 없이 재생됩니다.

**검증 기준은 화면에서 뽑습니다.** 매크로가 스스로를 검사하지 못하면 "버튼을 눌렀다"에 성공할 뿐이라, 마지막 액션이 만들어낸 것 중 가장 그 화면다운 것을 고릅니다 — 위 경로에서는 `텍스트 지우기`로, 손으로 쓴 매크로가 쓰는 것과 같은 기준입니다. 뽑을 수 없으면 저장하지 않습니다.

발화를 매크로에 맞추는 건 아직 **모델이 아니라 코드**입니다. [ADR 0006](docs/adr/0006-model-tiering.md)은 여기에 Haiku를 배정했고 매크로가 늘면 그래야 하지만, 모델을 먼저 넣으면 평범한 매칭이 무엇을 못 하는지 알 수 없습니다.

## 했다는 말은 증거가 아닙니다

탐색이 끝났다고 하면 **화면을 따로 읽어서 확인합니다.** 요청과 화면만 주고, 런이 무엇을 했는지는 알려주지 않습니다 — 알려주면 자기가 만든 이야기를 검토하게 되니까요.

유튜브 뮤직에서 "추천 노래 하나 틀어줘" 를 시켜보면, 곡까지 가서 재생을 누르지 않고 끝나는 런이 있습니다. 판정자는 플레이어 버튼이 `재생` 인지 `일시중지` 인지로 그걸 가려냅니다.

```
멈춘 화면:  버튼 "재생"      → 판정 "안 됐다"
재생 화면:  버튼 "일시중지"  → 판정 "됐다"
```

화면이 결론을 내주지 않으면 아니오입니다. 실패한 런은 다시 찾으면 되지만, **잘못된 성공은 저장되어 반복됩니다.**

## "그냥 매크로 녹화기 아닌가요"

가장 날카로운 반문이고, 답은 자가치유입니다. 앱이 바뀌어 셀렉터가 깨지면 **그 스텝만** 모델로 올라가고 고쳐진 셀렉터가 매크로에 되쓰입니다. 녹화기는 그걸 못 합니다.

앱 업데이트를 기다릴 필요 없이 잴 수 있습니다 — 셀렉터를 없는 식별자로 바꾸면 재설계가 남기는 상황과 같아집니다. 한 스텝만 아무것도 못 찾고 나머지는 멀쩡합니다.

```bash
npm run heal -- settings-open-accessibility
```

| 매크로 | 복구 없음 | 복구 있음 | 1런 | 2런 |
| --- | --- | --- | --- | --- |
| open-accessibility | 0/2 | **2/2** | $0.0069 · 14915ms | **$0 · 8912ms** |
| open-about | 0/2 | **2/2** | $0.0073 · 16309ms | **$0 · 10491ms** |
| search-open | 0/2 | **2/2** | $0.0068 · 21676ms | **$0 · 15490ms** |

**2런은 모델을 한 번도 부르지 않습니다.** 고쳐진 셀렉터가 파일에 써졌으니까요. 앱이 업데이트돼도 첫 실행만 느립니다.

고치는 것만큼 **안 고치는 것**도 정해뒀습니다. 좌표로 교체하려 할 때, 화면에 비슷한 게 없을 때, 그리고 **안전했던 스텝을 되돌릴 수 없는 컨트롤로 고치려 할 때** 거절합니다 — 사라진 `저장` 옆의 `삭제`는 화면상 가장 가까운 후보이고, 복구는 매크로에 영구히 써집니다. 자세한 건 [실측](docs/benchmarks/2026-09-09-self-healing-live.md)에.

## 진짜 아이폰에서

**iPhone 14 Pro / iOS 26.6 에서 돌아갑니다.** 탐색이 경로를 찾고, 재생이 모델 없이 3/3 재현했습니다.

셀렉터는 시뮬레이터에서 쓴 것이 **그대로 통했습니다.** 다른 건 화면 크기였습니다 — 실기기 설정은 Apple 계정·업데이트 알림·셀룰러가 위를 차지해서 `일반`이 화면 밖으로 밀립니다.

탐색은 스와이프를 스스로 넣어 해결했고, **재생은 복구를 부르기 전에 스크롤해 찾습니다** — 스크롤은 공짜고 복구는 모델 호출이니까요. 손으로 쓴 매크로가 그대로 `0/1 → 1/1` 이 됐고 모델은 한 번도 안 불렀습니다.

찾는 것만으로는 부족했습니다. **화면에 있는 것과 누를 수 있는 것이 다릅니다** — 852pt 화면의 y=748 에 있는 행은 WDA 가 보인다고 하고 셀렉터도 풀리는데 탭이 아무 일도 안 합니다. 한 번 더 스크롤해 y=593 으로 올리면 됩니다.

실행기 셋을 태스크 3개 × 5회씩, 실기기에서 45런:

| 태스크 | scripted | replay | explore |
| --- | --- | --- | --- |
| open-about | **0/5** | 5/5 | 5/5 · $0.0188 |
| open-accessibility | **0/5** | 4/5 | 5/5 · $0.0141 |
| search-open | 4/5 | 5/5 | 5/5 · $0.0126 |

`scripted` 는 스크롤이 없는 재생, `replay` 는 스크롤과 자가치유가 붙은 재생입니다. **두 태스크에서 0/5 가 5/5 가 되는데 모델 호출은 0회입니다.** 세 번째는 검색창이 첫 화면에 있어 스크롤이 필요 없고, 그래서 차이가 없습니다.

**느린 이유는 관찰입니다.** 트리 한 번 뜨는 데 1.6초(349KB)이고, WDA 설정도 병렬화도 줄이지 못했습니다. 대신 **덜 자주 보게** 했습니다 — 액션이 이미 돌려준 화면을 다음 관찰로 이어받아 스텝마다 왕복 하나를 없앴고, 탐색이 **52.8초에서 29초로** 줄었습니다. 모델 호출은 그대로입니다. 자세한 건 [실기기 측정](docs/benchmarks/2026-09-10-real-device.md)에.

### 연결하기

지금까지의 숫자는 전부 시뮬레이터에서 나왔습니다. 기기는 코드 서명과 포트 포워딩이 더 필요합니다.

```bash
scripts/preflight.sh      # Xcode · 서명 팀 · iproxy · 기기 · 키를 한 번에 확인
scripts/wda.sh --device   # 에이전트
npm run live              # 스모크 테스트
```

준비물과 처음 해볼 것들은 [`docs/real-device.md`](docs/real-device.md)에 있습니다.

## 기기 없이 돌려보기

실기기에서 캡처한 화면을 가짜 백엔드가 재생하므로, 클론하면 **기기·API 키·네트워크 없이** 경로를 걸어볼 수 있습니다.

```bash
npm install
npm run nubi -- demo
```

```
✓ 앱 실행               home -> home
✓ 검색 탭               home -> search-empty
✓ 검색어 입력             search-empty -> search-results
✓ 첫 결과 선택            search-results -> playing
✓ 재생 확인              playing -> playing
```

## 명령

| | 기기 | |
| --- | --- | --- |
| `npm test` | 불필요 | 순수 로직 + 가짜 백엔드 |
| `npm run nubi -- demo` | 불필요 | 녹화된 경로 재생 |
| `npm run nubi -- macros` | 불필요 | 매크로 라이브러리와 통계 |
| `npm run eval -- --fake` | 불필요 | 녹화 화면으로 태스크 실행 |
| `npm run check` | 불필요 | 타입 + 린트 + 테스트 + 문서 검사 |
| `npm run wda` | 시뮬레이터 | WebDriverAgent 빌드·실행 |
| `npm run live` | 필요 | 계약과 액션을 실기에 검증 |
| `npm run record -- settings` | 필요 | 앱을 걸어다니며 시나리오 녹화 |
| `npm run eval` | 필요 | 태스크 실행 + 측정 |
| `npm run report -- <macro>` | 필요 | 스텝별 화면이 붙은 실행 리포트 |

시뮬레이터면 전부 됩니다. 시뮬레이터용 WebDriverAgent는 코드 서명이 필요 없어서 **`npm run wda`가 SSH로도, 케이블 없이도, GUI 없이도** 동작합니다.

## 구조

```
Mac                                    iPhone
┌────────────────────────────┐
│  Orb      음성 입력·상태 표시  │
│   ↕                        │
│  Brain    라우팅 · 재생      │        ┌──────────────┐
│   │       · 복구            │        │  WDA         │
│   │       ↘ Anthropic API  │        │  (XCUITest)  │
│   ↓                        │        │      ↓       │
│  Hands    WDA 클라이언트     │──USB──▶│  대상 앱      │
│           세션 복구          │        └──────────────┘
│           트리 압축          │
└────────────────────────────┘               ▲
              │                              │
              └──── relay ──▶ 아이폰에서 승인
```

Hands는 서비스가 아니라 라이브러리입니다. Brain이 in-process로 import 합니다. 별도로 MCP 서버로도 노출해서, 개발 중에 Claude Code가 직접 폰을 조작할 수 있게 합니다.

**구현이 둘입니다** — WebDriverAgent를 조작하는 것과, 기기에서 녹화한 화면을 재생하는 것. 공통 계약 테스트를 양쪽에 돌립니다(`npm test`는 가짜에, `npm run live`는 실기에). 같은 인터페이스를 구현한다는 게 같은 동작을 보장하지 않기 때문입니다.

결제·삭제·전송처럼 되돌릴 수 없는 액션은 자동 실행되지 않습니다.

```
⊘ 실행 안 함  route
  터미널이 없어 물어볼 사람이 없습니다
```

**기본값은 거절입니다.** 게이트를 지정하지 않은 호출자, 터미널 없는 실행(cron·파이프), 시간 초과, 알 수 없는 답 — 전부 거절입니다. 승인되는 유일한 경우는 사람이 `승인`이라고 타이핑한 때이고, 엔터만 눌러 도달할 수 없게 단어로 뒀습니다.

요청에는 위험 등급이 아니라 **누를 컨트롤의 이름**이 들어갑니다. "위험합니다"는 누구도 의미 있게 승인할 수 없으니까요.

지금 게이트는 맥의 터미널입니다. 폰 화면이 아닌 것이 핵심입니다 — WDA가 폰 화면을 조작하므로 거기 그려진 승인 버튼은 **에이전트가 스스로 누를 수 있습니다**. 본래 채널은 기존 [pip-any](https://github.com/imjaewoo/pip-any) relay와 Live Activity이고, 터미널은 [ADR 0007](docs/adr/0007-approval-gate-off-device.md)이 명시한 폴백입니다.

## 진행 상황

다섯 단계로 만들고, 각 단계는 측정 가능한 산출물로 끝납니다.

| | 단계 | 산출물 | 상태 |
| --- | --- | --- | --- |
| 01 | Hands | 시뮬레이터에서 tap/type/assert, 세션 자동 복구 | 완료 |
| 02 | Trace + Eval | 측정 장치와 비교의 바닥 | 완료 |
| 03 | Brain · Explore | cold 성공률과 실제 토큰 비용 | 완료 |
| 04 | Macro · Replay + Repair | before/after 비교표 | 완료 |
| 05 | Orb + 승인 게이트 | 데모 | 진행 중 |

**eval을 매크로보다 먼저** 한 것은 의도적입니다. 빨라졌다는 걸 증명하려면 측정된 바닥이 필요하고, 그걸 기록할 기회는 한 번뿐입니다.

## 한계

먼저 밝힙니다. 전부 실제 제약입니다.

- **iOS가 세션 내내 "Automation Running" 배너를 띄우고**, 그동안 폰은 점유됩니다 — 사람이 동시에 쓸 수 없습니다.
- **무료 개발자 계정은 7일마다 WDA를 재설치해야** 합니다. 유료 계정이면 1년.
- **생체인증은 통과할 수 없습니다.** 이건 빠진 기능이 아니라 의도된 것이고, 승인 게이트가 그 자리를 대신합니다.
- **매크로는 앱 재설계에 취약합니다.** 자가치유가 완화하지만 없애지는 못하고, 접근성 트리가 부실한 앱은 좌표로 폴백해서 더 잘 깨집니다.
- 데모는 약관이 깨끗한 앱(음악·메모·미리알림·지도·설정)을 대상으로 합니다. 커머스 결제 자동화는 범위 밖입니다.
