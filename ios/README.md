# 폰 클라이언트

[슬라이스 1 — 빠른 모드](../docs/ios-client-slices.md#슬라이스-1--빠른-모드) 입니다. **맥도 relay 도 없이 폰 혼자 돕니다.** 엔진 코드(`src/`)에 의존하지 않습니다.

## 모양

**대화 하나, 화면 둘.** App Group 에 대화 기록을 하나 두고 앱과 잠금화면이 같이
씁니다. 잠금화면은 **마지막 한 턴을 비추는 창**이고 앱은 전체 스크롤입니다.
잠금화면에서 물은 것이 앱에 없고 앱에서 물은 것이 잠금화면에 한 줄만 남던 것을
없앱니다.

답은 두 조각으로 옵니다. **첫 줄은 한 문장 요약**이고 그다음부터가 자세한
설명입니다. 잠금화면은 요약만, 앱은 전문을 보여줍니다 — 모델 호출은 한 번입니다.

**홈은 서랍 넷입니다.** 관련된 것끼리 묶여 있고, 탭하면 그 안으로 들어갑니다.
입력줄은 홈에도 그대로 둡니다 — 어디서 시작하든 묻는 것이 가장 빠른 길이어야
합니다. 홈에서 물으면 대화 서랍으로 넘어갑니다.

| 화면 | 무엇 |
| --- | --- |
| 홈 | 서랍 넷과 입력줄. 준비가 덜 됐으면 시작하기 카드 |
| 일정 | 오늘·내일·이번 주, 목록, `+` 로 직접 추가 |
| 미리알림 | 안 끝난 것만. 동그라미를 누르면 완료 |
| 대화 | 말풍선, 출처 표시, 잠금화면에서 온 턴에 자물쇠 |
| 잠금화면 | 대화창 켜고 끄기, 단축어 만드는 법 |
| 설정 시트 | 권한 · 모델 · 대화 · 진단 |
| 잠금화면 대화창 | 물은 말, 요약, 오늘·내일·전문 버튼 |

색은 청록 하나만 씁니다. 강조가 둘이면 무엇이 중요한지 말하지 못합니다.

## 글자를 넣는 길은 단축어뿐이다

잠금화면에서 자유롭게 묻는 길은 **단축어 앱의 "텍스트 입력 요청"** 하나입니다.
인텐트가 직접 값을 요구하는 길(`requestValue`)은 첫 번만 열리고 막힙니다.

| 어디서 도는가 | 결과 |
| --- | --- |
| 확장 프로세스 | `LNActionExecutor 2010` |
| 앱 프로세스, 배경에 오래 | `Couldn't communicate with a helper application` |
| 앱 프로세스, 막 닫은 직후 | 됨 |

여덟 빌드를 같은 벽에 썼습니다. 벽이 아니라 문이 다른 데 있었습니다.
`AskNubiIntent` 는 이제 **받은 말에 답하기만** 하고, 묻는 일은 단축어가 합니다.
만드는 순서는 앱의 시작하기 카드에 있습니다.

## 무엇을 할 줄 아는가

**모델이 고릅니다.** 낱말 규칙으로 갈래를 정하던 것은 접었습니다 — "오늘 덥나" 를
날씨로, "여자친구랑 저녁 뭐 먹지" 를 그냥 답으로 보내는 일을 규칙으로 맞히려니
계속 어긋났고, 어긋날 때마다 프롬프트로 회피를 가르쳐 모델까지 쓸모없어졌습니다.
지금은 도구를 쥐여주고 무엇을 쓸지는 모델이 정합니다.

| 도구 | 하는 일 | 성격 |
| --- | --- | --- |
| `get_events` | 일정을 읽는다. 끝시각과 장소까지 준다 | 읽기 |
| `add_event` | 일정을 넣는다. 길이·장소를 같이 받는다 | **쓰기** |
| `propose_event_change` | 옮기거나 지우자고 제안만 한다 | 사람이 누름 |
| `get_reminders` · `add_reminder` · `complete_reminder` | 미리알림 | 하나는 읽기, 둘은 **쓰기** |
| `find_places` | 지금 자리에서 가까운 가게 (카카오 로컬, 없으면 애플 지도) | 읽기 |
| `get_weather` | 지금 날씨 (WeatherKit, 막히면 웹 검색으로 넘긴다) | 읽기 |

**예약·주문·전화·결제·메시지는 도구가 없습니다.** 대신 일정에 넣어주고 전화는
직접 해야 한다고 말합니다. 없는 일을 했다고 말하는 것은 아래에서 코드가 막습니다.

잠금화면 버튼처럼 **글자가 정확히 일치하는 말**(`오늘 일정`, `할일`)만 모델을
건너뛰고 25ms 쯤에 답합니다 — `Shared/FastPath.swift`. 그 밖에는 전부 모델을
거칩니다. 앱 안의 직접 추가와 단축어 경로는 아직 `Shared/DateTalk.swift` 가
말을 시각으로 읽습니다.

## 겹치는 일정은 코드가 먼저 본다

일정을 넣을 때 **그 시간대에 이미 있는 것을 도구가 확인해서 알려줍니다.**

모델이 스스로 "8시 30분 하체운동이랑 겹치는데 옮길까요" 라고 한 적이 있었지만
그건 일정을 읽다가 우연히 본 것이었습니다. 다음에도 그런다는 보장이 없습니다.
`Events.clashes(with:minutes:)` 가 넣기 **전에** 봅니다 — 넣고 나서 보면 자기
자신이 걸립니다. 옮기자고 제안할 때는 **옮길 자리**도 같이 봅니다. 옮겼는데
거기도 겹치면 옮기나 마나입니다.

종일 일정은 세지 않습니다. 하루를 통째로 덮어서 전부 겹침이 됩니다.

## 장소를 넣으면 아이폰이 출발 시각을 알려준다

`add_event` 는 `place` 를 받습니다. **좌표가 붙은 일정에는 캘린더가 교통 상황을
보고 "지금 나가야 합니다" 를 띄웁니다.** 우리가 이동 시간을 계산할 이유가
없습니다 — 애플이 이미 합니다.

좌표는 `find_places` 가 찾아준 순간에 App Group 에 적어둡니다. 그 다음 말이
"거기로 일정 잡아줘" 인 경우가 많은데, 이름만 넣으면 글자일 뿐이고 좌표가
붙어야 알림이 옵니다.

## 한 일이 없으면 했다고 말할 수 없다

`ToolRun.wrote` 는 `add_event` · `add_reminder` · `complete_reminder` 만 세웁니다.
쓰는 도구를 부르지 않았는데 답에 "했어", "잡았어", "넣었어" 같은 말이 있으면
`Model.honest(_:wrote:)` 가 한 줄을 붙입니다.

> (실제로는 아직 아무것도 하지 않았습니다.)

**말로는 못 막았습니다.** 프롬프트에 세 번 적었고 세 번 다 샜습니다. 마지막은
"유촌참치마을 예약 오늘 저녁 7시 반으로 잡았어" 였고, 그 턴에 돈 도구는 일정
읽기 하나뿐이었습니다. 예약 도구는 아예 없습니다.

## 스파이크가 정한 것

[잠금화면 스파이크](../docs/benchmarks/2026-09-24-lockscreen-spike.md)에서 나온 규칙이 코드에 그대로 박혀 있습니다.

| 규칙 | 어디에 |
| --- | --- |
| 확장은 권한을 요청하지 않는다 — 요청하면 대화상자 없이 거부로 굳는다 | `Shared/Events.swift` |
| 권한은 앱이 받는다 | `App/NubiApp.swift` 의 설정 화면 |
| 확장이 잠금 상태에서 EventKit 에 닿는다 | `Shared/TodayIntent.swift` |
| 되는데 안 보이면 사람은 다시 누른다 | 활동 갱신이 실패하면 기록에 남긴다 |
| TestFlight 에는 콘솔이 없다 — App Group 기록이 유일한 출구다 | `Shared/NubiLog.swift` |

그 기록이 빌드 1 에서 바로 값을 했습니다. 잠금화면 버튼이 일정은 읽는데 화면에는
아무것도 안 떴고, 기록에만 이유가 있었습니다.

```
[활동] 시작 실패 … Target does not include NSSupportsLiveActivities plist key
[오늘] 오늘 추석 (종일) — 42ms
```

**`NSSupportsLiveActivities` 는 앱에만 두면 부족합니다.** 잠금화면 버튼은 확장
프로세스에서 `Activity.request` 를 부르고, 그 타깃의 Info.plist 를 봅니다. 앱에서
띄울 때는 멀쩡하기 때문에 앱만 써보면 드러나지 않습니다.

## API 키

**저장소에 들어가지 않습니다.** 앱 설정 화면에서 붙여넣으면 키체인에 저장됩니다 ([ADR 0001](../docs/adr/0001-separate-public-repo.md)). 빌드에 넣으면 `.ipa` 안에 들어갑니다.

확장과 공유하지 않습니다. 키가 필요한 것은 앱의 자유 질문뿐이고, 잠금화면 버튼은 EventKit 만 씁니다.

## 빌드

서명 자료도 저장소 밖입니다. 환경변수로 받습니다.

```bash
cd ios/Nubi
NUBI_TEAM_ID=... NUBI_BUILD=1 NUBI_SIGN_ID=... xcodegen generate
```

TestFlight 배포는 [플레이북](../docs/ops-testflight.md)에 있습니다. 구성별로 서명이 갈립니다 — Debug 는 자동(Xcode 로 폰에 직접 꽂는 경로), Release 는 수동 + 이름 붙은 프로파일(archive).

## 아직 없는 것

작업 모드입니다. relay 도, 맥과의 페어링도, 승인 게이트도 없습니다 — [슬라이스 2](../docs/ios-client-slices.md#슬라이스-2--작업-모드) 이고, 그 앞에 조작 폰 준비가 있습니다.
