# 폰 클라이언트

[슬라이스 1 — 빠른 모드](../docs/ios-client-slices.md#슬라이스-1--빠른-모드) 입니다. **맥도 relay 도 없이 폰 혼자 돕니다.** 엔진 코드(`src/`)에 의존하지 않습니다.

## 모양

**대화 하나, 화면 둘.** App Group 에 대화 기록을 하나 두고 앱과 잠금화면이 같이
씁니다. 잠금화면은 **마지막 한 턴을 비추는 창**이고 앱은 전체 스크롤입니다.
잠금화면에서 물은 것이 앱에 없고 앱에서 물은 것이 잠금화면에 한 줄만 남던 것을
없앱니다.

답은 두 조각으로 옵니다. **첫 줄은 한 문장 요약**이고 그다음부터가 자세한
설명입니다. 잠금화면은 요약만, 앱은 전문을 보여줍니다 — 모델 호출은 한 번입니다.

**홈은 서랍 넷입니다.** 관련된 것끼리 묶여 있고, 탭하면 그 안으로 들어갑니다.
입력줄은 홈에도 그대로 둡니다 — 어디서 시작하든 묻는 것이 가장 빠른 길이어야
합니다. 홈에서 물으면 대화 서랍으로 넘어갑니다.

| 화면 | 무엇 |
| --- | --- |
| 홈 | 서랍 넷과 입력줄. 준비가 덜 됐으면 시작하기 카드 |
| 일정 | 오늘·내일·이번 주, 목록, `+` 로 직접 추가 |
| 미리알림 | 안 끝난 것만. 동그라미를 누르면 완료 |
| 대화 | 말풍선, 출처 표시, 잠금화면에서 온 턴에 자물쇠 |
| 잠금화면 | 대화창 켜고 끄기, 단축어 만드는 법 |
| 설정 시트 | 권한 · 모델 · 대화 · 진단 |
| 잠금화면 대화창 | 물은 말, 요약, 오늘·내일·전문 버튼 |

색은 청록 하나만 씁니다. 강조가 둘이면 무엇이 중요한지 말하지 못합니다.

## 글자를 넣는 길은 단축어뿐이다

잠금화면에서 자유롭게 묻는 길은 **단축어 앱의 "텍스트 입력 요청"** 하나입니다.
인텐트가 직접 값을 요구하는 길(`requestValue`)은 첫 번만 열리고 막힙니다.

| 어디서 도는가 | 결과 |
| --- | --- |
| 확장 프로세스 | `LNActionExecutor 2010` |
| 앱 프로세스, 배경에 오래 | `Couldn't communicate with a helper application` |
| 앱 프로세스, 막 닫은 직후 | 됨 |

여덟 빌드를 같은 벽에 썼습니다. 벽이 아니라 문이 다른 데 있었습니다.
`AskNubiIntent` 는 이제 **받은 말에 답하기만** 하고, 묻는 일은 단축어가 합니다.
만드는 순서는 앱의 시작하기 카드에 있습니다.

## 무엇을 할 줄 아는가

**모델이 고릅니다.** 낱말 규칙으로 갈래를 정하던 것은 접었습니다 — "오늘 덥나" 를
날씨로, "여자친구랑 저녁 뭐 먹지" 를 그냥 답으로 보내는 일을 규칙으로 맞히려니
계속 어긋났고, 어긋날 때마다 프롬프트로 회피를 가르쳐 모델까지 쓸모없어졌습니다.
지금은 도구를 쥐여주고 무엇을 쓸지는 모델이 정합니다.

| 도구 | 하는 일 | 성격 |
| --- | --- | --- |
| `get_events` | 일정을 읽는다. 끝시각과 장소까지 준다 | 읽기 |
| `add_event` | 일정을 넣는다. 길이·장소를 같이 받는다 | **쓰기** |
| `propose_event_change` | 옮기거나 지우자고 제안만 한다 | 사람이 누름 |
| `get_reminders` · `add_reminder` · `complete_reminder` | 미리알림 | 하나는 읽기, 둘은 **쓰기** |
| `remind_at_place` | 그 자리에 닿으면 울리는 미리알림 | **쓰기** |
| `find_places` | 지금 자리에서 가까운 가게 (카카오 로컬, 없으면 애플 지도) | 읽기 |
| `get_weather` | 지금 날씨 (WeatherKit, 막히면 웹 검색으로 넘긴다) | 읽기 |
| `set_timer` · `get_timers` · `cancel_timer` | 몇 분 뒤 알림 | 둘은 **쓰기** |
| `remember` · `forget` | 오래 기억할 것 | **쓰기** |

출처 꼬리표는 **어느 도구가 돌았는지**를 말합니다. 알림과 기억을 그 판단에서
빠뜨려 둘 다 "모델" 로 찍히던 때가 있었는데, 그러면 화면만 봐서는 도구가 돈
건지 모델이 지어낸 건지 갈리지 않습니다.

**예약·주문·결제·메시지는 도구가 없습니다.** 대신 일정에 넣어주고, 가게 번호가
있으면 **전화 버튼**을 띄웁니다 — 거는 것은 사용자입니다. 없는 일을 했다고 말하는
것은 아래에서 코드가 막습니다.

잠금화면 버튼처럼 **글자가 정확히 일치하는 말**(`오늘 일정`, `할일`)만 모델을
건너뛰고 25ms 쯤에 답합니다 — `Shared/FastPath.swift`. 그 밖에는 전부 모델을
거칩니다. 앱 안의 직접 추가와 단축어 경로는 아직 `Shared/DateTalk.swift` 가
말을 시각으로 읽습니다.

## 기억

대화 기록은 최근 여섯 턴만 보냅니다. 그래야 하기 때문입니다 — 그래서 다이어트
중인 것도, 헬스장이 어딘지도 매번 다시 말해야 했습니다.

`Shared/Memory.swift` 에 **서른 개, 한 줄 예순 자**까지 적어두고 매 요청의
시스템 프롬프트에 붙입니다. 상한이 있는 이유는 전부 매번 올라가기 때문입니다.

| 종류 | 예 | 수명 |
| --- | --- | --- |
| 사실 | 영통 산다, 차 없다 | 안 늙음 |
| 선호 | 매운 거 못 먹는다 | 안 늙음 |
| 상태 | 다이어트 중, 감기 | **90일 뒤 "오래됨" 표시** |
| 장소 | 집, 회사, 헬스장 — **좌표까지** | 안 늙음 |

상태는 늙어도 **지우지 않습니다.** 지우면 왜 잊었는지 모릅니다. 표시만 붙고,
누비가 아직 맞는지 슬쩍 확인합니다.

장소가 특별합니다. 좌표가 붙어야 "집에 도착하면 알려줘" 가 됩니다 —
`remind_at_place` 가 방금 찾은 가게 다음으로 여기를 봅니다.

### 안 받는 것

**여섯 자리 넘게 이어진 숫자가 있으면 거부합니다.** 카드번호·주민번호·비밀번호가
들어갈 자리를 코드로 없앱니다. 프롬프트로 막을 일이 아닙니다 —
[세 번 샜던 자리](#한-일이-없으면-했다고-말할-수-없다)와 같은 성격입니다.

그리고 **말할 때만 기억합니다.** 대화를 몰래 훑어서 사실을 캐지 않습니다.
기억할 때는 답에 그렇게 말합니다. 조용히 기억하는 물건은 무섭습니다.

### 보이기

설정 › 기억. 종류별로 묶여 있고, 언제부터 알고 있는지와 자리를 아는지가
줄마다 보입니다. 스와이프로 하나씩, 아래에서 전부 지웁니다.

**보이고 지울 수 있는 것이 기능이 아니라 조건입니다.** 한 번 잘못 들어간 기억은
그 뒤 모든 답의 바닥이 됩니다.

### 끼워 맞추지 않기

다이어트 중이라고 회식 메뉴까지 샐러드를 권하면 안 씁니다. 프롬프트에 한 줄
박혀 있습니다 — **지금 한 말이 기억보다 우선이다.**

## 버튼은 모델이 고른 곳을 가리킨다

길찾기 버튼은 늘 **첫 번째 검색 결과**를 가리켰습니다. 그런데 모델이 두 번째를
권한 적이 있습니다 — 샤브향을 권해놓고 버튼은 해안선으로 갔습니다. 누른 사람은
엉뚱한 데로 갑니다.

이제 답이 나온 뒤에 **그 글 안에 방금 찾아준 가게 이름이 있는지 봅니다.**
있으면 길찾기와 전화를 그 가게로 맞춥니다. 모델에게 도구를 하나 더 부르게 하지
않았습니다 — 왕복이 한 번 더 늘고, 안 부르면 또 어긋납니다.

## 날씨는 두 곳에 묻는다

WeatherKit 이 며칠째 `WDSJWTAuthenticatorServiceListener.Errors error 2` 였습니다.
스크립트로 볼 수 있는 것은 전부 맞았습니다 — 앱 ID 에 `WEATHERKIT` 이 등록돼
있고, ipa 에 권한이 있고, 프로파일에도 들어 있습니다. 남은 것은 동의 대기 중인
계약인데 그건 웹에서만 보입니다.

**남의 승인을 기다릴 자리가 아니었습니다.** 날씨는 기능 하나가 빠진 게 아니라
아침 브리핑과 모델 맥락까지 같이 죽는 자리입니다.

애플을 먼저 보고, **세 번 연달아** 거절당하면 하루 물러나 Open-Meteo 로 갑니다.
가입도 키도 없고 한국은 기상청 모델을 섞어 씁니다. 하루 뒤에는 다시 애플을
봅니다 — 계약이 풀렸을 수도 있고, 그러면 더 정확한 쪽으로 돌아갑니다.

한 번 튕겼다고 물러나지 않는 이유는, 멀쩡한 쪽을 하루 동안 안 쓰게 되기
때문입니다. `error 2` 는 세 번 연달아 나야 성질이 다른 실패입니다.

기상청 API 를 직접 쓰지 않은 것은 **키를 또 받아야 하고** 좌표를 격자로 바꿔야
해서입니다. 지금 필요한 것은 오늘 되는 것이었습니다.

## 타이머는 알림이지 알람이 아니다

아이폰에는 **앱이 시계 앱 타이머를 거는 공개 길이 없습니다.** 그래서 알림으로
합니다. 소리가 나고 화면이 켜지는 것은 같지만 무음 스위치를 넘지는 못합니다.

미리알림으로도 되지만 그건 목록에 남는 물건입니다. 라면 3분은 목록에 남을 일이
아닙니다.

### 타이머가 돌면 카드가 타이머가 된다

흐르는 숫자를 말풍선 아래에 곁다리로 붙여봤는데 **잠금화면에서 읽히지
않았습니다.** 볼 것이 그거일 때는 그것만 크게 있어야 합니다.

타이머가 도는 동안 카드는 큰 숫자와 끄는 버튼입니다. 타이머를 건 그 턴이면
숫자만 있고, 그 뒤에 다른 것을 물었으면 **답 한 줄이 위에 붙습니다** — 답을
통째로 가리면 잠금화면에서 못 봅니다.

끄는 버튼이 없으면 안 됩니다. 크게 띄워놓고 앱을 열어 말로 꺼야 한다면 큰
숫자는 구경거리일 뿐입니다.

타이머를 걸면 대화창에 **스스로 세는 글자**가 붙습니다. `Text(timerInterval:)`
은 위젯이 직접 갱신하므로 우리가 1초마다 밀어 올릴 필요가 없습니다 — 그렇게
했다면 실시간 활동 갱신 한도에 금방 걸렸을 겁니다.

**어느 턴에서 밀어 올리든 붙습니다.** 타이머를 건 그 턴에만 보이면 다음 질문을
하는 순간 초가 사라집니다. 그래서 `LiveAnswer.push` 가 밀어 올릴 때마다 걸려
있는 알림을 한 번 봅니다.

`Date.now...ends` 는 끝이 앞서면 안 되는 범위입니다. **위젯은 타이머가 끝난
뒤에도 다시 그려질 수 있어서** 지난 시각으로 범위를 만들면 죽습니다. 끝났으면
0:00 을 글자로 보여줍니다.

울릴 시각은 **식별자에서 읽습니다.** `nextTriggerDate()` 는 한 번만 울리는
방아쇠에 nil 을 돌려주는 경우가 있고, 그러면 방금 건 타이머가 "없음" 으로
보입니다 — 3분 타이머를 걸고 3초 뒤 물었더니 "이미 끝났다" 고 답했습니다.
우리가 붙인 이름이 가장 확실합니다.

## 겹치는 일정은 코드가 먼저 본다

일정을 넣을 때 **그 시간대에 이미 있는 것을 도구가 확인해서 알려줍니다.**

모델이 스스로 "8시 30분 하체운동이랑 겹치는데 옮길까요" 라고 한 적이 있었지만
그건 일정을 읽다가 우연히 본 것이었습니다. 다음에도 그런다는 보장이 없습니다.
`Events.clashes(with:minutes:)` 가 넣기 **전에** 봅니다 — 넣고 나서 보면 자기
자신이 걸립니다. 옮기자고 제안할 때는 **옮길 자리**도 같이 봅니다. 옮겼는데
거기도 겹치면 옮기나 마나입니다.

종일 일정은 세지 않습니다. 하루를 통째로 덮어서 전부 겹침이 됩니다.

## 방금 넣은 것을 또 넣지 않는다

"예약하자" 로 오늘 8시 반을 넣고, 24초 뒤 "저녁약속을 내일로" 라고 하자 내일
것을 **하나 더** 넣었습니다. 옮긴 게 아니라 둘이 됐고, 답은 "내일 8시 반으로
잡았어" 였습니다. 거짓말은 아니지만 사용자는 옮긴 줄 압니다. 정직 검사는 이걸
못 잡습니다 — 실제로 쓰긴 썼으니까요.

10분 안에 **비슷한 제목**의 일정을 다른 시각으로 또 넣으려 하면 넣지 않고
돌려보냅니다. 비슷한지는 글자 두 개씩 겹치는 비율로 봅니다 — "여자친구와 저녁 -
샤브향 수원매탄점" 과 "여자친구 저녁 샤브샤브" 는 낱말로는 '저녁' 하나만
겹치는데 사람이 보기엔 같은 약속입니다.

## 장소를 넣으면 아이폰이 출발 시각을 알려준다

`add_event` 는 `place` 를 받습니다. **좌표가 붙은 일정에는 캘린더가 교통 상황을
보고 "지금 나가야 합니다" 를 띄웁니다.** 우리가 이동 시간을 계산할 이유가
없습니다 — 애플이 이미 합니다.

좌표는 `find_places` 가 찾아준 순간에 App Group 에 적어둡니다. 그 다음 말이
"거기로 일정 잡아줘" 인 경우가 많은데, 이름만 넣으면 글자일 뿐이고 좌표가
붙어야 알림이 옵니다.

## 한 일이 없으면 했다고 말할 수 없다

`ToolRun.wrote` 는 `add_event` · `add_reminder` · `complete_reminder` 만 세웁니다.
쓰는 도구를 부르지 않았는데 답에 "했어", "잡았어", "넣었어" 같은 말이 있으면
`Model.honest(_:wrote:)` 가 한 줄을 붙입니다.

> (실제로는 아직 아무것도 하지 않았습니다.)

**말로는 못 막았습니다.** 프롬프트에 세 번 적었고 세 번 다 샜습니다. 마지막은
"유촌참치마을 예약 오늘 저녁 7시 반으로 잡았어" 였고, 그 턴에 돈 도구는 일정
읽기 하나뿐이었습니다. 예약 도구는 아예 없습니다.

### 바로잡는 것으로는 부족했다

"타이머 껐어" 라고 답하고 `cancel_timer` 를 안 불러서 3분 뒤 그대로 울린 적이
있습니다. 한 줄 붙여 바로잡기만 하면 **사람이 다시 말해야 합니다.**

이제 도구를 안 부르고 했다고 말하면 **그 자리에서 한 번 되돌려보냅니다** —
"아무 일도 일어나지 않았다, 정말 할 거면 지금 도구를 불러라". 한 번만 그럽니다.
그래도 안 부르면 그때 한 줄을 붙입니다.

**도구가 늘면 할 수 있다고 말할 거리도 같이 늡니다.** 검사 낱말에 끄고 지우고
취소하고 저장하는 말을 더했습니다.

## 스파이크가 정한 것

[잠금화면 스파이크](../docs/benchmarks/2026-09-24-lockscreen-spike.md)에서 나온 규칙이 코드에 그대로 박혀 있습니다.

| 규칙 | 어디에 |
| --- | --- |
| 확장은 권한을 요청하지 않는다 — 요청하면 대화상자 없이 거부로 굳는다 | `Shared/Events.swift` |
| 권한은 앱이 받는다 | `App/NubiApp.swift` 의 설정 화면 |
| 확장이 잠금 상태에서 EventKit 에 닿는다 | `Shared/TodayIntent.swift` |
| 되는데 안 보이면 사람은 다시 누른다 | 활동 갱신이 실패하면 기록에 남긴다 |
| TestFlight 에는 콘솔이 없다 — App Group 기록이 유일한 출구다 | `Shared/NubiLog.swift` |

그 기록이 빌드 1 에서 바로 값을 했습니다. 잠금화면 버튼이 일정은 읽는데 화면에는
아무것도 안 떴고, 기록에만 이유가 있었습니다.

```
[활동] 시작 실패 … Target does not include NSSupportsLiveActivities plist key
[오늘] 오늘 추석 (종일) — 42ms
```

**`NSSupportsLiveActivities` 는 앱에만 두면 부족합니다.** 잠금화면 버튼은 확장
프로세스에서 `Activity.request` 를 부르고, 그 타깃의 Info.plist 를 봅니다. 앱에서
띄울 때는 멀쩡하기 때문에 앱만 써보면 드러나지 않습니다.

## API 키

**저장소에 들어가지 않습니다.** 앱 설정 화면에서 붙여넣으면 키체인에 저장됩니다 ([ADR 0001](../docs/adr/0001-separate-public-repo.md)). 빌드에 넣으면 `.ipa` 안에 들어갑니다.

확장과 공유하지 않습니다. 키가 필요한 것은 앱의 자유 질문뿐이고, 잠금화면 버튼은 EventKit 만 씁니다.

## 빌드

서명 자료도 저장소 밖입니다. 환경변수로 받습니다.

```bash
cd ios/Nubi
NUBI_TEAM_ID=... NUBI_BUILD=1 NUBI_SIGN_ID=... xcodegen generate
```

TestFlight 배포는 [플레이북](../docs/ops-testflight.md)에 있습니다. 구성별로 서명이 갈립니다 — Debug 는 자동(Xcode 로 폰에 직접 꽂는 경로), Release 는 수동 + 이름 붙은 프로파일(archive).

## 아직 없는 것

작업 모드입니다. relay 도, 맥과의 페어링도, 승인 게이트도 없습니다 — [슬라이스 2](../docs/ios-client-slices.md#슬라이스-2--작업-모드) 이고, 그 앞에 조작 폰 준비가 있습니다.
