# LockScreen 스파이크

[슬라이스 1](../../docs/ios-client-slices.md) 의 설계를 가르는 미확인 두 가지를 실기기에서 확인합니다.

**버릴 코드입니다.** 여기서 얻은 답만 문서로 옮기고 이 디렉터리는 지웁니다. 엔진 코드에 의존하지 않고, 슬라이스 1 에 그대로 옮기지 않습니다.

## 무엇을 묻는가

| | 질문 | 왜 설계를 가르는가 |
| --- | --- | --- |
| **A** | `LiveActivityIntent` 가 앱을 포그라운드로 깨우지 않고 처리되는가. 그 안에서 **네트워크를 칠 수 있는가**, 얼마나 오래 도는가 | 승인 게이트는 relay 에 답을 보내야 합니다. 확장이 직접 못 치면 앱을 깨워야 하고, 그러면 잠금 상태에서의 승인이 다른 물건이 됩니다 |
| **B** | 잠금 상태에서 Control 위젯 → App Intent 가 **EventKit 읽기/쓰기**를 하는가 | 빠른 모드의 완료 조건 *"잠금 상태에서 제어 센터 버튼만으로 미리알림이 추가된다"* 가 여기 달려 있습니다 |

## 준비

빌드는 시뮬레이터로 확인했습니다(`BUILD SUCCEEDED`). 실제 확인은 **잠금 상태가 필요하므로 실기기에서만** 됩니다.

```bash
cd spikes/LockScreenSpike
xcodegen generate
open LockScreenSpike.xcodeproj
```

Xcode 에서 팀을 고르고 두 타깃(`LockScreenSpike`, `SpikeWidget`)을 실기기에 설치합니다. App Group `group.dev.jaewoo.nubispike` 이 두 타깃 모두에 붙어 있어야 합니다 — 기록을 공유하는 통로입니다.

**또는 TestFlight 로 받습니다.** 잠금화면 동작을 보려면 케이블을 빼야 하고, 빼면 Xcode 콘솔이 없습니다. TestFlight 로 받으면 폰만 들고 확인할 수 있습니다 — 절차와 직접 해야 하는 단계는 [TestFlight 배포](../../docs/ops-testflight.md) 에 있습니다.

**개인 폰(iPhone 18 Pro)에 넣습니다.** 이 스파이크는 다른 앱을 건드리지 않습니다. 미리알림을 하나 추가하는 것이 전부이고, 제목에 `스파이크 확인` 이 붙습니다. 끝나면 [치우기](#치우기) 절차로 되돌립니다.

## A — 승인 버튼

1. [ ] 앱을 열고 **Live Activity 시작** 을 누른다
2. [ ] 잠금화면에 활동이 보이는지 확인한다
3. [ ] **폰을 잠근다** (화면을 끄고 다시 켜서 잠금화면을 본다)
4. [ ] 잠금화면의 **승인** 버튼을 누른다
5. [ ] 누른 직후 **앱이 열렸는지** 눈으로 확인한다 — 이게 A 의 핵심
6. [ ] 앱을 열어 **기록**을 읽는다

기록에서 볼 것:

- `[승인버튼] 시작` 과 `[승인버튼] 끝 …ms` 사이의 시간
- `[승인버튼] 네트워크 성공 HTTP 200` 인가 `네트워크 실패` 인가
- `앱이 포그라운드로 올라옴` 이 **승인버튼 줄들보다 뒤에 있는지** — 뒤에 있고 내가 직접 앱을 연 것이라면 버튼은 앱을 깨우지 않은 것입니다

### 결과 (실행 후 적을 것)

| 항목 | 결과 |
| --- | --- |
| 버튼을 눌렀을 때 앱이 열렸는가 | **아니오** — 눈으로 확인. 잠금화면에 그대로 머물렀습니다 |
| Live Activity 가 잠금화면에 떴는가 | **예** |
| 네트워크 호출 | **성공 HTTP 200** — 빌드 1·2 합쳐 11번 모두 |
| 인텐트 소요 시간 | **캐시를 끈 빌드 2 에서 775 / 786 / 804 / 992ms** |
| 화면이 꺼진 채(잠금 + 대기)에서도 동작했는가 | 예 — 2분 간격을 두고 누른 3·4 번째도 동작 |
| 기타 관찰 | 아래 |

기록 원문:

```
2026-09-24T06:40:53Z  앱이 포그라운드로 올라옴
2026-09-24T06:40:59Z  [앱] Live Activity 시작
2026-09-24T06:41:11Z  [승인버튼] 시작 / 네트워크 성공 HTTP 200 / 끝 194ms
2026-09-24T06:41:14Z  [승인버튼] 시작 / 네트워크 성공 HTTP 200 / 끝 4ms
2026-09-24T06:43:04Z  [승인버튼] 시작 / 네트워크 성공 HTTP 200 / 끝 1ms
2026-09-24T06:43:06Z  [승인버튼] 시작 / 네트워크 성공 HTTP 200 / 끝 3ms
```

빌드 1 에서 1ms 가 나왔을 때 캐시를 의심했고, **빌드 2 에서 캐시를 끄자 그대로
드러났습니다.**

| | 빌드 1 (기본 캐시) | 빌드 2 (캐시 끔 + URL 에 타임스탬프) |
| --- | --- | --- |
| 첫 호출 | 194ms | 992ms |
| 이후 | 1~4ms | 775 · 786 · 804 · 844ms, 한 번은 **2016ms** |

**1~4ms 는 `URLCache` 였습니다.** 진짜 왕복은 **0.8~1.0초이고, 2 초까지 벌어집니다.**

이 숫자가 설계를 바꿉니다. 승인 응답을 확장에서 직접 보내면 **버튼을 누르고 약 1 초
동안 아무 일도 일어나지 않습니다.** 공개 인터넷 상대라 tailnet 안이면 더 짧겠지만,
공짜가 아니라는 것은 그대로입니다. 그 1 초를 비워두면 사용자는 다시 누릅니다 —
실제로 그렇게 됐습니다. **`ContentState` 를 네트워크보다 먼저 바꿔야 합니다.** 2 초짜리가 섞이는 이상
"곧 끝나니까 괜찮다" 로는 넘어갈 수 없습니다.

빌드 2 의 `06:54:34` 두 줄이 그 증거입니다. **같은 초에 인텐트가 두 개 겹쳐 돌았습니다** —
앞의 것이 네트워크를 기다리는 사이에 한 번 더 눌린 것입니다.

**버튼을 눌러도 화면에서는 아무 일도 일어나지 않습니다.** 인텐트가 Live Activity 를
갱신하지 않으므로 표시가 그대로입니다. 누른 사람 입장에서는 고장난 버튼과 구별되지
않습니다 — 기록을 봐야 돌았다는 것을 알 수 있습니다. **슬라이스 2 에서는 인텐트가
ContentState 를 즉시 바꿔야 합니다.** 그게 없으면 사용자는 두 번 세 번 누릅니다.
실제로 여기서도 네 번 눌렸습니다.

**`앱이 포그라운드로 올라옴` 이 버튼 기록 뒤에 없다** 는 것도 그대로 읽으면 안
됩니다. 그 줄은 `onAppear` 가 남기는데, **배경에서 돌아올 때는 `onAppear` 가 다시
불리지 않습니다.** 앱이 이미 메모리에 있었으므로 버튼이 앱을 깨웠더라도 줄이 안
남을 수 있습니다. 앱이 열리지 않았다는 판단은 **눈으로 본 것**에 근거합니다.

## B — 제어 센터 버튼

**순서가 중요합니다.** 권한을 받기 전과 받은 뒤를 둘 다 봐야 "확장이 권한을 못 받는다" 와 "아무도 권한을 준 적이 없다" 가 갈립니다.

1. [ ] **설정 › 제어 센터** 에서 **Spike EventKit** 을 추가한다
2. [ ] **권한을 주기 전에** 폰을 잠근 채 버튼을 누른다 — 대조군
3. [ ] 앱을 열어 **3. 권한** 절의 **권한 요청** 을 누르고 둘 다 허용한다
4. [ ] **다시 폰을 잠그고** 제어 센터 버튼을 누른다
5. [ ] 앱을 열어 **새로고침** 을 누르고 기록을 읽는다
6. [ ] **미리 알림** 앱에서 `스파이크 확인 …` 항목이 생겼는지 확인하고 지운다

앱을 배경에서 다시 불러오는 것만으로는 화면이 갱신되지 않습니다. **새로고침을 눌러야 합니다.**

기록에서 볼 것:

- `[EventKit] 일정 읽기 성공 — N건` 인가 `권한 거부됨` 인가
- `[EventKit] 미리알림 쓰기 성공` 인가 실패인가
- 잠금 상태에서 **권한 대화상자가 뜨는지** — 뜬다면 잠금 상태에서는 쓸 수 없다는 뜻이고, 앱을 먼저 한 번 열어 권한을 받아두는 설계가 됩니다

### 결과 (실행 후 적을 것)

#### 권한을 주기 전 (빌드 1)

| 항목 | 결과 |
| --- | --- |
| 잠금 상태에서 버튼이 눌리는가 | **예** — 확장 안에서 인텐트가 끝까지 돕니다 |
| 일정 읽기 | 권한 거부됨 |
| 미리알림 쓰기 | 권한 거부됨 |
| 권한 대화상자가 떴는가 | **아니오** |
| 인텐트 소요 시간 | 21~29ms, 5회 모두 |

```
2026-09-24T06:46:28Z  [EventKit] 시작 / 일정 권한 거부됨 / 미리알림 권한 거부됨 / 끝 29ms
2026-09-24T06:46:47Z  (같음) 25ms
2026-09-24T06:46:49Z  (같음) 21ms
2026-09-24T06:46:52Z  (같음) 22ms
2026-09-24T06:48:28Z  (같음) 24ms
```

**여기까지로는 답이 갈리지 않습니다.** 빌드 1 의 앱에는 권한을 요청하는 자리가 아예
없었습니다. 그래서 상태가 "아직 묻지 않음" 인 채로 확장이 요청했고, 대화상자 없이
곧바로 거부로 떨어졌습니다. 25ms 는 아무것도 기다리지 않았다는 뜻입니다.

확인된 것은 **하나뿐**입니다 — 잠금 상태에서 Control 위젯이 확장 안에서 인텐트를
끝까지 돌립니다. 그것만으로도 진입점으로서는 살아 있습니다.

확인되지 않은 것은 **권한이 있을 때 EventKit 에 닿는가** 입니다. 빌드 2 에 앱에서
권한을 받는 자리를 넣었습니다.

#### 권한을 준 뒤 (빌드 2)

| 항목 | 결과 |
| --- | --- |
| 요청 전 상태가 무엇으로 찍혔는가 | **`거부됨`** — `아직 묻지 않음` 이 아니었습니다 |
| 앱에서 권한 요청 | 일정 **허용**, 미리알림 **허용** |
| 일정 읽기 | **성공 — 2건** |
| 미리알림 쓰기 | **성공** |
| 잠금 상태에서 대화상자가 떴는가 | 아니오 (권한을 받은 뒤라 뜰 이유가 없습니다) |
| **잠금 상태가 확실한가** | **예** — 잠금화면 스크린샷의 시계와 기록이 같은 분입니다 |
| 인텐트 소요 시간 | 첫 492ms, 이후 65 · 66ms |

```
06:54:36  [EventKit] 시작 — 일정 거부됨, 미리알림 거부됨 → 둘 다 거부 / 26ms
06:54:38  (같음) 23ms
06:54:52  [앱] 일정 권한 요청 → 허용
06:54:54  [앱] 미리알림 권한 요청 → 허용
06:54:57  [EventKit] 일정 읽기 성공 — 2건 / 미리알림 쓰기 성공 / 끝 492ms
06:57:21  (같음) 끝 65ms   ← 잠금화면 버튼
06:57:24  (같음) 끝 66ms   ← 잠금화면 버튼
```

**권한만 있으면 확장이 EventKit 에 읽고 씁니다.** 읽기도 쓰기도 됩니다.

마지막 두 줄이 결정적입니다. `06:57` 의 잠금화면 스크린샷과 같은 분이고, 그
스크린샷에서 왼쪽 아래 버튼이 `Spike EventKit` 입니다. **폰이 잠긴 채, 잠금화면
버튼만으로 미리알림이 추가됐습니다.** [슬라이스 1 의 완료 조건 2](../../docs/ios-client-slices.md)
가 그대로 성립합니다.

두 번째부터 65ms 인 것은 확장 프로세스가 살아 있기 때문입니다. 첫 호출의 492ms 는
프로세스를 띄우는 값이고, **잠금화면에서 처음 누르는 사람이 겪는 것은 이쪽**입니다.

### 확장이 권한을 물으면 조용히 거부로 굳는다

요청 전 상태가 `거부됨` 이었다는 것이 이 스파이크에서 가장 값진 줄입니다.

앱은 그때까지 권한을 **한 번도 요청한 적이 없습니다.** 정상이라면 `아직 묻지 않음`
이어야 합니다. 그런데 `거부됨` 이었습니다. **빌드 1 에서 확장이 요청한 것이 상태를
거부로 바꿔버린 것입니다.** 대화상자는 뜬 적이 없고, 사용자는 거절한 적이 없습니다.

| 언제 | 상태 |
| --- | --- |
| 아무것도 안 했을 때 | `아직 묻지 않음` (이어야 함) |
| 확장이 요청한 뒤 | **`거부됨`** — 묻지 않고 |
| 앱이 요청한 뒤 | `전체 허용` |

**회복은 됩니다** — 앱에서 요청하면 대화상자가 제대로 뜨고 허용됩니다. 하지만 그
사이 빠른 모드는 "권한 거부" 로 답했을 것이고, 사용자는 자기가 거절한 기억이
없으니 설정에서 고칠 생각도 못 합니다.

**슬라이스 1 의 규칙: 권한은 앱이 먼저 받는다. 확장은 상태를 읽기만 하고, 없으면
요청하지 말고 "앱에서 한 번 열어달라" 고 말한다.**

## 답이 설계를 어떻게 바꾸는가

**A 는 첫 줄, B 는 첫 줄입니다 — 둘 다 가장 좋은 경우입니다.**

| A 의 답 | 슬라이스 2 |
| --- | --- |
| **앱을 안 깨우고 네트워크도 됨 ← 이것** | 승인이 잠금화면에서 즉시 끝납니다. 가장 좋은 경우 |
| 앱을 안 깨우지만 네트워크는 안 됨 | 버튼이 App Group 에 답만 적고, 앱이나 백그라운드 작업이 relay 로 옮깁니다. 지연이 생깁니다 |
| 앱을 깨움 | 잠금 해제가 필요해집니다. "잠금화면 승인" 을 접고 알림 탭 → 앱 → 승인 으로 설계를 바꿔야 합니다 |

| B 의 답 | 슬라이스 1 |
| --- | --- |
| **읽기·쓰기 다 됨 ← 이것** | 완료 조건 2 를 그대로 둡니다 |
| 읽기만 됨 | 빠른 모드의 쓰기 동작은 앱을 열어야 합니다. 완료 조건을 고칩니다 |
| 둘 다 안 됨 | Control 위젯은 진입점으로 쓰지 않고 App Shortcut 만 남깁니다 |

## 치우기

개인 폰에 넣고 확인했으므로, **흔적을 남기지 않고 걷어냅니다.**

1. [ ] 결과 표를 채워 [슬라이스 계획](../../docs/ios-client-slices.md) 으로 옮긴다
2. [ ] **미리 알림** 앱에서 `스파이크 확인 …` 으로 시작하는 항목을 전부 지운다 — **세 개입니다** (`06:54:57`, `06:57:21`, `06:57:24`)
3. [ ] **설정 › 제어 센터** 에서 `Spike EventKit` 컨트롤을 제거한다
